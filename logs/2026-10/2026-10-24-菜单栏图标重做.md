# 菜单栏图标重做（2026-10-24）

依据：《菜单栏图标重做任务书 V1.0》。只改托盘资源、生成器与测试；未改应用图标、托盘四态与菜单，未评价观感、未截图。

## 问题

上一版 `tray-template@2x.png` 是**两个粗逗号**（引号），不是规格里的三条竖波；笔画约 4pt，明显重于 macOS 菜单栏常见的 1.2–1.5pt。

## 新几何（22pt 设计单位）

| 元素 | 值 |
| --- | --- |
| 画布 | 22×22 pt |
| 竖条宽度 | 1.5 pt |
| 条间距 | 3 pt |
| 高度（左→右） | 6.5 / 11 / 8.5 pt |
| 圆头半径 | 0.75 pt |
| 垂直中线 | y = 11（三根对称） |
| 整组宽度 | 10.5 pt，左起 5.75（水平居中） |
| 颜色 | macOS 纯黑 #000000；Windows 纯白 #FFFFFF；背景全透明 |

三份产出都由同一组参数按 `size / 22` 缩放：

- `tray-template.png` 22×22 — `c3d30758703b12cd2492ee4440100e280db0f41e9b4f54f07964a68524bcd58b`
- `tray-template@2x.png` 44×44 — `7bfdaca31b2ca6aae7a51b22fc54ba2b058034f92cc254481a9d46b347a9fa13`
- `tray-windows.png` 32×32 — `b4add488375f7f68ac285a56902992a454a7dca58bb02019e5338f4ebec5fddb`

## 生成器

- `scripts/gen-tray-icon.py` 重写为上述几何的单一参数表；仍是纯标准库、4 倍超采样、生成后回读校验、重复运行字节一致。
- `scripts/gen-quote-icon.py` 不再生成任何托盘资源（避免它覆盖菜单栏图标）；应用图标、`.icns/.ico`、Windows 标志与 favicon 逻辑不变。
- `scripts/test-tray-icon.py` 重写为 7 条断言，包含任务书要求的形状/粗细与面积上限。

## 断言与实测

- 三份文件存在，尺寸 22/44/32，RGBA；四角 alpha=0。
- **@2x y=22 水平扫描：恰好 3 段**，段区间 `(11–14) (20–23) (29–32)`，每段 4px（3±1），空隙 5px（6±1）。
- **不透明像素（alpha=255）占比**：22px 2.9%、44px 5.0%、32px 4.7%，均 ≤12%。
- macOS 模板可见像素为纯黑；Windows 同形状、可见像素 RGB ≥240。
- 重复运行 `gen-tray-icon.py` 三份字节一致；`test-tray-icon.py` 7/7、`test-quote-icon.py` 5/5 通过。

## 安装与构建环境（如实记录）

- 为在本机菜单栏查看，重新打包并覆盖安装了本机 Pro 的应用（1.3.0-beta.1，pid 87150）；`codesign --verify --deep --strict` 通过，二进制内已嵌入新的 22px 模板。
- 从零重建 release 时，当前 Xcode 21 / ld 27037 + `strip = true` 产出的部分 proc-macro dylib 带 `mis-aligned LINKEDIT string pool`，dyld 拒绝加载（`phf_macros`、`derive_more_impl`、`serde_derive` 等，`cargo build` 报 "can't find crate"）。改用 `CARGO_PROFILE_RELEASE_STRIP=none` 后构建与运行正常。这是本机构建链问题，与本次资源无关；已发布的 1.3.0-beta.1 dmg 由此前缓存产物构建，不受影响。
- 因此本机安装的这份是 `strip=none` 的本地构建，**与 release 资产不同**；本轮未重新发布，菜单栏图标是否进入正式安装包等 Timmy 验收后再决定。
- 构建产生的 `target/` 保留（含 sherpa-onnx 预编译库；当前 Xcode 的 strip 问题也说明不宜在没有预编译库的情况下清空重建）。
