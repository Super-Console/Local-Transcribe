# CLI 与 MCP 能力对等（2026-10-24）

依据：《CLI 与 MCP 能力对等任务书 V1.0》。未修改任务书。CLI/MCP 都是服务客户端，所有 LAN 写操作走共享的 `voice-to-text-lan::settings`。

## 已完成

- **共享设置**：`crates/lan-compute/src/settings.rs`（`lan-settings.json` 的唯一读写入口）。文件不存在读默认值；损坏内容先改名成 `.corrupt-<unix_ms>` 再回落；写入走临时文件 + 原子改名 + 回读；`update()` 用 fs2 文件锁串行化跨进程读-改-写。host 不做 IP 解析。
- **服务层**：`crates/transcription-service/src/lan.rs`，请求枚举新增 `LanAdd / LanRemove / LanEnable / LanDisable / LanSet / LanScan / LanStartLocal / LanStopLocal / LanStartRemote / LanStopRemote / LanStatus / LanNodeProbe / LanMode`。
- **CLI**：`lan list|nodes|add|remove|enable|disable|set|scan|start|stop|status` 与 `mode local|prefer-lan`；全部 JSON 输出，退出码 0/1/2/4；`lan start` 无参数＝本机，带 id/名称＝远端；LAN 命令客户端读超时 90s。
- **MCP**：新增 `add_node / update_node / remove_node / node_status`，共 13 个工具；只能操作已保存节点，`add_node` 是唯一能引入新地址的入口；连接服务前先校验 host（拒绝 `://`、空白、shell 元字符、以 `-` 开头）。
- **节点**：`local-transcribe-node --from-settings` 从共享设置读名称/网卡/端口/模型目录；`detach_from_terminal()` 让节点脱离 SSH/GUI 会话并把 stdio 落到 `lan-host/lan-node.log`。
- **远端启停**：只走系统 sshd；`ssh -o BatchMode=yes -o ConnectTimeout=10 <target> '<node_binary> --from-settings'`；启动后轮询 `/api/v1/capabilities` 最多 60s；失败打印远端日志最后 20 行或 ssh stderr；停止读远端 `lan-node.json` 的 pid → `kill -INT`（不用 -9），10s 仍活着如实报告。未安装任何 LaunchAgent/launchd/systemd/计划任务。
- **文档**：README 双语补 CLI 命令面、退出码、host 语义；点明 tailnet/VPN 节点不会被自动发现、需手动添加；点明 `ssh` 字段按发起端填写（Air 上 `ssh pro`，Pro 上 `ssh air`）。`docs/mcp.md` 更新为 13 个工具。`lan add` 的不可达报错也带同一句别名提醒。
