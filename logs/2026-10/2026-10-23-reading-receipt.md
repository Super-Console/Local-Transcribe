## 二、七个核对问题（只依据任务书）

1. **P3.5 的前置是 P2 还是 P3？**
   → **P2**。阶段索引第 4 行写「P2（不需要 P3）」。

2. **掩码是 /31 或 /32 时，对端过滤怎么处理？**
   → **不做过滤**。这两个长度无法定义「同子网对端」，放行所有能路由到该地址的对端；该行为必须在 UI 与日志明示。

3. **绑 0.0.0.0 时为什么禁止 `enable_addr_auto()`？**
   → 它会把本机所有地址（包括 tailnet 的 `100.x`）写进 A 记录，LAN 邻居会再次拿到不可达地址，等于把 1.1 的幽灵节点换个入口重演；`0.0.0.0` 只能显式宣告一个 RFC1918 地址。

4. **改成从 store 读最近 N 条，还缺什么、必须新增什么？**
   → 缺**枚举 API**。`JobStore` 现在只有 `job_status` 与 `active_job_status`，必须新增（例如 `recent_jobs(limit)`）去扫描 `jobs/*.json`、按时间取最近 N 条。

5. **为什么已安装模型列表不许直接改 `display_name`？**
   → 它被首页模型菜单、历史等多处共用，直接改会扩大影响面（并会污染已写入的历史/跨进程数据）；只能在渲染时转换。

6. **`prettyName` 必须对哪两种输入形态都成立？**
   → 带家族前缀的 **id**（`{family_prefix}-{文件夹名}`）与**纯文件夹名**（`display_name`）。

7. **P5 打包的前置条件是哪几个阶段？**
   → **P3.5 与 P4.x**（即 P4、P4.1、P4.2）；阶段索引第 8 行如此规定。
