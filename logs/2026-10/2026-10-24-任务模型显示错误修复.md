# 任务模型显示错误修复（2026-10-24）

依据：《任务模型显示错误修复任务书 V1.0》。只改"描述这条结果"的模型来源；未修改任何任务书，未改模型选择、派发与 `selected-model.json`。本轮在 MacBook Pro（`Tim's MacBook Pro`）上执行，未做人工界面验收、不评价观感。

## 现象与根因（已核实）

- 远端节点模型转写成功后，结果页模型一栏显示「未选择」。
- `apps/desktop/src/lib/components/TranscribeView.svelte` 的模型行读的是 `+page.svelte` 的 `model`（`get_selected_model` = 当前选中），不是这条记录的 `model_id`。远程任务时本机选择为空，于是落到 `common.notSelected`。
- 记录侧已有正确数据：`Transcript.model_id`（camelCase `modelId`）由服务端 / GUI 的 LAN 路径写入；远端任务的值为节点模型 id（`inspect_model_directory` 生成的 `family-目录名`，见 `crates/transcription-core/src/asr.rs` 的 `id: format!("{family_prefix}-{directory_name}")`）。
- 历史卡片与历史详情本就用 `entry/hit/detail.modelId`，只是没有兜底。

## 改动

- `TranscribeView.svelte`：删除 `model: ModelSummary | null` 入参，改为 `modelId: string | null`；模型行改为 `prettyName(modelId) || t("common.unknownModel")`。组件内不再出现 `common.notSelected`、`model?.displayName`。
- `+page.svelte`：
  - 新增 `startedModelId`，在 `startTranscription` 时按"这一刻任务会用的模型"取值（`remoteSelection?.modelId ?? model?.id`）；新增 `taskModelId = $derived(transcript?.modelId?.trim() || startedModelId)`。
  - 在回到首页、结果页返回、外部（CLI/MCP）任务接管三处清空 `startedModelId`，避免把旧任务的模型带到下一条记录。
  - 结果页改用 `modelId={taskModelId}`；顶栏 `AppToolbar {model}` 与设置页 `{model}` 保持"当前选中"语义不变。
- `HistoryView.svelte`：历史卡片、搜索结果卡片、历史详情的模型名都加 `|| t("common.unknownModel")`。
- 五语言新增 `common.unknownModel`（zh 未知模型 / en Unknown model / de Unbekanntes Modell / es Modelo desconocido / fr Modèle inconnu）；`common.notSelected` 保留未删。
- 导出：JSON 本来直接序列化该 jobId 的 `Transcript`（`export_transcript` → `load_transcript` → `to_json`），`modelId` 即记录的模型。额外修了一个同源缺陷：历史详情页导出原先因 `if (!job && !transcript) return` 直接无反应，现改为 `transcript?.jobId ?? job?.jobId ?? detailJobId`，默认文件名取 `detail.sourceFileName`。
- `crates/transcription-service/src/lib.rs`：新增测试 `export_json_uses_the_recording_model_not_a_current_selection`（写入一条 `model_id` 的记录 → 导出 JSON → 断言 `modelId` 等于记录值）。
