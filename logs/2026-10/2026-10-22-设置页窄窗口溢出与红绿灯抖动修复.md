# 2026-10-22 设置页窄窗口溢出与红绿灯抖动修复

## 任务来源

Timmy 反馈两个问题：

1. 设置页没有做窄窗口适配：窗口横向缩得很小时，右侧文字（值、链接）超出窗口右边界被裁掉。
2. 调整窗口大小时红绿灯一直在抖动，体验不好。

## 根因

### 问题 1：窄窗口下整条布局比窗口宽

表面上是 `.value` 里长英文 token（`sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25`）溢出，实际根因在布局链上游：

- `+page.svelte` 的 `.body` 是 `.app` 的 flex item，但**没有 `min-width: 0`**。
- flex item 的自动最小尺寸 = min-content；而 `.content` 里有 MCP 代码块（`white-space: pre` 的超长行）和长路径，把 min-content 顶到 1600px+。
- 于是 `.body`/`.main`/`.content`/`.set` 整条比窗口宽，所有行都被窗口右边缘整齐裁掉——`.value` 只是被推着走的受害者。

中间走过两步弯路（均记录，避免重复）：

- 先给 `.row` 加 `flex-wrap: wrap`、`.value` 改 `flex: 0 1 auto; min-width: 0; overflow-wrap: anywhere`——治标，行仍然溢出。
- 用 CUA 截图核对时一度怀疑是截图裁剪假象；经截图尺寸（1214×1366，比例 0.889）与窗口尺寸（640×720，比例 0.889）比对一致，确认溢出为真。

### 问题 2：红绿灯抖动 + 修复过程引入崩溃

- 抖动根因：旧代码在每个 `WindowEvent::Resized` 里强摆按钮 frame，与 macOS 自己在缩放期间持续重置按钮位置互相打架，来回闪。
- 第一版修复（防抖线程里直接 `setFrameOrigin`）**引入了启动后崩溃**（2 次，`voice-to-text-desktop-2026-10-22-203233/203422.ips`）：
  - 崩溃栈：`objc_exception_throw ← -[NSWindow(Regions) _postWindowNeedsToResetDragMargins] ← -[NSView setFrameOrigin:] ← -[_NSThemeWidget setFrameOrigin:]`。
  - 根因：AppKit 只能在主线程调用；防抖用的 `std::thread` 在后台线程直接挪了标准窗口按钮，抛 ObjC 异常。
  - 该崩溃与设置页修改无关，纯粹是红绿灯防抖第一版的线程错误。

## 修改

1. `apps/desktop/src/routes/+page.svelte`：`.body` 增加 `min-width: 0`，断开 min-content 传导（一行，真正的修复）。
2. `apps/desktop/src/lib/components/SettingsView.svelte`（保留的加固）：
   - `.row` 加 `flex-wrap: wrap`；
   - `.value` 改 `flex: 0 1 auto; min-width: 0; overflow-wrap: anywhere; max-width: 100%`。
3. `apps/desktop/src-tauri/src/lib.rs`：
   - `place_traffic_lights` 改为**代际计数防抖**（`PLACE_GENERATION` + `PLACE_SETTLE_MS = 150ms`）：缩放过程中不摆，停手 150ms 后只摆一次；
   - `Focused(true)` 时立即摆一次（此时 macOS 才重置按钮）；
   - 防抖线程到点后通过 `app.run_on_main_thread` **回主线程**再 `setFrameOrigin`，杜绝跨线程 AppKit 调用。

## 验证

- `npm run check`：0 errors / 0 warnings；`cargo check -p voice-to-text-desktop` 无错误。
- 构建、替换安装（旧 .app 移入废纸篓 `Local Transcribe-<stamp>.app`）、重启。
- CUA 实测（截图尺寸与窗口尺寸比例均核对一致，非裁剪假象）：
  - 640×720：右侧值与链接（模型 id + 管理模型、1 个·954 MB、4 条·1 MB、复制配置）全部收进窗口内；MCP 长行改为在代码块内部横向滚动。
  - 480×620：同样无溢出。
  - 连续 10 次交替缩放（520↔780 宽）后进程存活（pid 72145），无新崩溃报告（崩溃目录里只有修复前 20:32/20:34 的两份）。
  - 恢复 900×620：侧栏回归、红绿灯位置正常（24/44/64 绝对位）。

## 回归风险

- 本次崩溃教训：**任何 AppKit 调用（含 `setFrameOrigin` 挪标准按钮）必须在主线程**；以后涉及窗口 chrome 的改动要先跑一次「启动 + 缩放」冒烟并查 `~/Library/Logs/DiagnosticReports/`。
