# 首页删除与模型页去重（2026-10-24）

依据：《首页删除与模型页去重任务书 V1.0》。未修改任务书；未评价观感、未截图。

## 首页卡片删除

- `HistoryView.svelte`：卡片右键、`Shift+F10`、`ContextMenu` 键都打开同一个单条目菜单（只有「删除」）；点击外部、`Esc`、窗口缩放都会关闭。卡片保持 `tabindex=0`，键盘可聚焦。
- 运行中的任务：菜单项 `disabled`，下方提示「请先取消该任务」。`+page.svelte` 用 `runningJobId` 派生值传入，避免在 `{:else}` 分支里做窄化表达式。
- 确认弹窗：标题「删除这条记录？」，正文含文件名，并写明「只删除本应用的记录与任务状态，不会动原始音视频文件」；按钮沿用 `common.cancel` / `common.delete`。
- 后端命令 `delete_history_entry(job_id)`（`apps/desktop/src-tauri/src/lib.rs`）：
  - 先过 `is_safe_job_id`（小写字母/数字/连字符，≤64），`../outside` 之类直接拒绝；
  - 运行中（内存状态或持久化状态）拒绝，返回「请先取消该任务」；
  - 只处理 `transcripts/<id>.json`、`jobs/<id>.json`、`jobs/<id>.cancel`，逐个 `fs::rename` 到 `~/.Trash`；目标名带来源目录，避免两个 `<id>.json` 互相覆盖；
  - `jobs/.dispatch.lock` 与原始媒体不在候选路径里；
  - 缺失的文件记入 `skipped`，不当作错误；移动失败直接报错；
  - 返回 `DeleteOutcome { removed, skipped }`，前端据此显示「已删除 N 项记录」（4 秒后消失），并清掉内存里的 transcript / job / source path；若正在看该条，退回首页。
- 测试（Rust）：`delete_history_tests` 4 条——三件文件都进临时废纸篓且锁与源媒体不动、缺失文件记 skipped、运行中拒绝、危险 id 拒绝。

## 模型页去重

- 删除原先在页面下半部分重复列出的已安装模型列表；清单里的模型只在上方「准确优先 / 速度优先 / 辅助模型」各出现一次。
- 新增 `model-names.js::catalogEntryFor()`（`prettyNameFrom` 复用它），用于判断某个已安装 id 是否属于清单。
- 仅当存在清单之外的已安装模型时，底部才渲染「其它已安装」小节（`extraModels.length > 0`）；没有就不渲染，也不留空标题。该小节保留「设为默认 / 删除」与合计脚注。
- 三组标题与「辅助模型（标点）」保持不变。
