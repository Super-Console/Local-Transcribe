# 并发设置测试自我复制事故修复（2026-10-24）

## 事故现象

- 整机进程数被耗尽：`zsh: fork failed: resource temporarily unavailable`、`spawn ... EAGAIN`。npm / rustc / Chrome / 系统 mdworker 都无法启动；`npm run check`、`cargo test`、两条 Chrome 测试全部失败于 EAGAIN，而代码本身未报错。
- `ps ax` 显示数百个 `target/debug/deps/voice_to_text_lan-f5f841c15a344fc1` 进程，进程链逐级生成（PPID 依次指向同二进制），随时间持续增加。

## 根因（已核实）

- `crates/lan-compute/src/settings.rs` 的单测 `two_processes_editing_different_nodes_lose_nothing` 用 `std::env::current_exe()` 启动"子进程"。
- 在 **单元测试** 里 `current_exe()` 指向测试二进制本身，不是 `local-transcribe-node`。子进程没有命中 `VOICE_TO_TEXT_LAN_SETTINGS_HOLDER` 的入口处理（那段在节点二进制的 `main` 里），于是重跑整套测试，又执行同一个测试、再起两个子进程 —— 每代翻倍，直到进程表耗尽。
- 该测试本身此前也从未真正验证目标：子进程写的是设置文件，但父进程读到的可能来自另一条路径/进程；事故前它也没有被单独观察到通过。

## 处置

- `pkill -TERM -f "target/debug/deps/voice_to_text_lan-"` 终止全部自我复制进程；随后 `pgrep` 无残留，系统恢复可 fork。
- 删除 `settings.rs` 中那段单测，在 `crates/lan-compute/tests/settings_concurrency.rs` 重写为**集成测试**：用 `env!("CARGO_BIN_EXE_local-transcribe-node")` 启动子进程；节点二进制 `main` 第一行就是 `settings_test_helper()`（写完即 `exit(0)`），不会再递归。
- 在 `settings.rs` 原位留下注释，说明为什么禁止用 `current_exe()`。
- 顺手修正同文件另一个自写测试的无效输入：`an_invalid_idle_unload_falls_back_on_its_own` 原 JSON 用了 `"mode":"local"`，而 `LanMode` 的反序列化只接受 `local_only` / `prefer_lan`（`local` 只被 `LanMode::parse` 接受）。整份设置因此反序列化失败、回落到默认值，测试断言 600 被"回落"掩盖。改为 `"mode":"local_only"` 后测试才真正检验空闲档位。

## 验证

- 运行 `settings_concurrency` 前先确认无残留：`pgrep -f voice_to_text_lan-` 为空。
- `cargo test -p voice-to-text-lan`：36 unit + 19 node + 10/1 ignored + 4 + 2 + 1（settings_concurrency，0.92s）全部通过，无进程堆积。
- `cargo test --workspace`：全部通过。
- `npm test`（apps/desktop）：47/47 通过，两条此前因 EAGAIN 失败的真实组件/浏览器用例恢复通过。

## 影响范围与防复发

- 影响对象：本机进程表（短暂影响所有应用的进程创建），以及 `voice-to-text-lan` 的测试代码。
- 未删除任何用户文件；未改动产品运行逻辑。
- 防复发：跨进程测试只经 `CARGO_BIN_EXE_*` 子进程入口；单元测试不得以 `current_exe()` 作为"另一个进程"的默认实现。
