## 2. 目标行为

1. 界面与命令行都能在**任意非回环 IPv4 接口**上监听，包括 Wi-Fi / 以太网 / USB 网卡 / VPN / Tailscale。
2. 也能显式选择「所有接口（0.0.0.0）」。
3. **仍然禁止静默扩大范围**：用户没选的情况下不得回退到 0.0.0.0，不得自动换网卡，不得因为上次的网卡消失就自己挑一个。
4. 启动后在 UI 与状态文件里如实显示**实际绑定的地址**，让人一眼能看出"现在是对所有接口开放，还是只对一个地址开放"。

## 3. 技术规格

### 3.1 三处必须改的代码

| 文件 | 现状 | 要改成 |
| --- | --- | --- |
| `apps/desktop/src-tauri/src/lan_host.rs` → `interfaces()` | 只收 `name.starts_with("en")` 且 `address.is_private()` | 收**所有非回环 IPv4 接口**（含 `utun*` / `tun*` / `ppp*`），带回名称与掩码；可过滤 `169.254/16` 链路本地 |
| `crates/lan-compute/src/node.rs` → `LanScope::new` | `if !address.is_private()` 直接拒绝 | 改为「**非回环 + 合法掩码**」即可 |
| `crates/lan-compute/src/node.rs` → `LanScope::allows` | `ip.is_private() && 同子网` | 去掉 `is_private()` 要求，只按掩码判定（见 3.2） |

### 3.2 掩码语义矩阵（这一条最容易踩）

Tailscale 的 `utun` 接口掩码通常是 **/32**。如果只删掉 `is_private()` 而**保留子网判定**，`/32` 会要求对端与本机地址完全相同，结果是**所有 tailnet 对端一律被 403 `lan_only` 拒绝**——而且现象是"连得上、但被拒"，非常难查。

必须按接口类型区分：

| 掩码 | 语义 | 对端过滤 |
| --- | --- | --- |
| `0.0.0.0`（用户显式选择「所有接口」） | 绑定全部接口 | **不做过滤** |
| `/1` – `/30` | 正常子网（家庭 / 公司 LAN） | 保留「同子网放行、跨子网拒绝」 |
| `/31`、`/32` | 点对点（Tailscale、部分 VPN） | **不做过滤** |

要点：

- `/31` 与 `/32` 时无法定义"同子网对端"，所以只能放行所有能路由到该地址的对端。这一行为必须在 UI 与日志里明示，不得静默。
- **不得**为了省事把 `/24` 等正常子网的过滤一并去掉——那是把现有防线白白削掉，而它并不妨碍 Tailscale。

### 3.3 命令行参数

- `--netmask <掩码>` 改为**可选**：`--listen` 为 `0.0.0.0` 或掩码本身为 `/31`、`/32` 时不需要；其余情况仍需提供，缺失时报错（退出码 2）并说明原因。
- `--listen` 仍**不设默认值**（必填），保持主任务书 P2 第 4 条的结论。
- 启动日志与 `lan-node.json` 状态文件必须记录：绑定地址、掩码、以及**对端过滤是否启用**（`subnet_filter: same_subnet | none`）。

### 3.4 与 macOS 入站授权的关系

绑定 100.x 地址并不绕过 macOS 的入站连接授权。若另一台设备连接时仍被系统拦截（与主任务书 §4 第 10 条记录的既有现象相同），按该条要求记录 ALF 证据并标记 blocked，**不要试图代点系统弹窗**。

## 6. 测试（TDD，先红后绿）

1. `LanScope::new` 接受 `100.64.0.1/255.255.255.255`；拒绝回环地址与非法掩码（如 `0.0.0.0` 掩码、非连续掩码）。
2. `/32` 时**不对对端过滤**：tailnet 对端放行（用假对端地址断言，不依赖真网络）。
3. `0.0.0.0` 时不做过滤，且状态里标明 `subnet_filter: none`。
4. `/24` 保持原语义：同子网放行、跨子网拒绝（**这条必须留着**，防止顺手把防线删了）。
5. `interfaces()` 的筛选逻辑抽成纯函数后测试：`utun4` + 100.64/10 **必须出现在结果里**；回环不出现；`en0` + 192.168 仍出现。
6. `--netmask` 缺失时：`/24` 场景报错退出码 2；`/32` 与 `0.0.0.0` 场景不报错。

## 7. 验收（替代主任务书 §4 第 8 条）

1. 本机 `--listen <Tailscale 地址>:7878` 起节点成功，同机 `curl http://<tailscale 地址>:7878/api/v1/health` 返回 `ok`。
2. 从 tailnet 内另一台设备（Air）请求 `/api/v1/capabilities`：成功放行；若被 macOS 拦截，记录 blocked 与 ALF 证据。
3. 绑定 `192.168.x.x/24` 的旧用法不受影响：局域网内仍可发现与提交。
4. 绑定 `0.0.0.0` 时状态里 `subnet_filter: none`，UI 文案为「所有网络接口都可访问」。
5. 网卡消失（例如关闭 Tailscale）后重启应用：**不启动节点**，提示上次接口不可用，不得静默改绑。
