# Local Transcribe — iOS + Android 移动端开发任务书 V1.0

> **交付对象：** 可自主执行的软件开发 Agent（OpenCode 等）  
> **性质：** 可执行的工程任务书；不仅是产品创意或 UI 说明  
> **项目名称：** Local Transcribe（不得误写为 subscribe）  
> **目标：** 开发 iOS 和 Android 双平台移动客户端：手机录音、可靠保存、发现桌面计算节点、传输音频、远程转写、接收与查看结果。  
> **任务依赖：** 优先复用桌面端已有的 Local Transcribe LAN Compute V1.1 协议及转写任务核心。  
> **版本定位：** Mobile Early Beta；不得将未测试的功能标称为稳定可用。

## 1. 产品定位与功能范围

### 1.1 目标体验

用户打开 iPhone 或 Android 手机上的 Local Transcribe：

1. 点击录音，锁屏或切到其他 App 后仍能在系统允许的条件下持续录制。
2. 停止录音后先**完整保存到手机本地**，立即显示录音条目。
3. 使用先前选择的首选计算节点（Mac / Windows），在相同局域网且节点在线时自动上传。
4. 计算节点按其队列规则、使用节点已安装且兼容的 ASR 模型转写。
5. 手机查看上传进度、排队、准备中、转写中、完成/失败等真实状态；断线以后能够恢复。
6. 结果同步回手机，以**阅读式、只读文字**显示，支持复制与导出 TXT/JSON；始终保留原始录音。

### 1.2 本版本必须实现

- iOS 与 Android **真实原生录音能力**，支持锁屏持续录制的可行实现。
- 录音开始、暂停/继续（系统能力允许时）、停止；实时计时、电平指示、明显录制状态。
- 录音可靠写盘、异常恢复、低存储空间处理、录音列表与回放。
- 局域网 mDNS / DNS-SD 发现 Mac/Windows 计算节点；手动 IP:port 回退。
- 显式选择并记住首选设备，读取远程可用模型；用户可改选模型。
- 前台自动上传、分块与断点续传/幂等提交（依后端协议能力），网络断开安全重试。
- 后台上传的最佳可行实现，并准确呈现系统限制；不能承诺无条件即时上传。
- 查询远程任务队列与实时进度/稳定文本片段；重连后补齐事件，避免重复结果。
- 本地记录所有录音、关联任务、转写结果与同步状态。
- 深浅色主题、简洁易用 UI、系统无障碍与中英文本国际化架构（中文界面可优先完成，至少保证英文文案完整可切换）。
- 基础隐私说明、权限说明、日志脱敏、退出/卸载时数据行为明确。
- 可复现构建脚本、测试、Android 安装包与 iOS 构建产物（分发限制见第 11 节）。

### 1.3 暂不开发

- 手机端大型 ASR 模型推理或模型文件导入。
- 手机端捕获第三方应用内部音频、系统混音录音、通话偷录。
- 手机上的多音轨应用级捕获（桌面端已规划，移动端 MVP 只录麦克风）。
- 云服务器、云端账户、订阅计费、云存储、互联网直连穿透。
- AI 总结、翻译、字幕生成、说话人自动识别等非核心功能。
- Home Assistant 自动开机：列为后续**可选扩展**，不可阻塞移动端验收。
- 自动扫描局域网并未经用户选定即将音频发往任意设备。

## 3. 技术选型

优先评估 **Flutter（Dart UI + 必要的原生 Swift/Kotlin 插件）** 或 **React Native**，选择对项目现状、原生录音/后台上传、构建维护最友好的方案；不要为追求表面代码统一而牺牲 iOS/Android 后台录音可靠性。也可以使用原生 SwiftUI + Kotlin/Compose，前提是提供合理的维护成本依据。

无论框架，以下部分必须使用适当原生能力：

- **iOS**：AVAudioSession / AVAudioRecorder 或 AVAudioEngine；正确配置 `UIBackgroundModes` audio；麦克风权限；系统可用的后台 `URLSession` 文件上传与委托恢复；Bonjour / 本地网络权限。
- **Android**：AudioRecord / MediaRecorder 或兼容音频 API；适当的 microphone 类型前台服务及常驻通知；对应 Android 版本的权限与前台服务规则；可靠的 WorkManager 等延期传输机制；必要时按系统版本使用系统推荐的长时间数据传输方式。
- 移动端本地数据库可选 SQLite；文件必须存储在系统分配的 App 数据目录，避免不必要的媒体库/文件系统广泛权限。
- 与节点通信使用清晰的 API 客户端层，不将网络协议耦合在 UI 控件内。

**最低支持系统版本以能可靠实现关键功能和真实测试结果为准，明确写入 README；不得伪称旧版本全兼容。**

## 4. 手机端 UI / UX 规范

视觉延续 Local Transcribe 桌面端：Apple 原生感 + 现代极简 + 克制的 Liquid Glass 质感，不使用过分晶莹的高光、彩色卡片墙或管理后台式界面。

信息架构三处核心入口：

1. **录音**：首页，明显的开始/暂停/停止控件、持续时间、输入电平、当前使用的麦克风、录制状态。支持系统锁屏录音状态及中断恢复提示。
2. **录音库**：按日期排列；文件名可修改；显示长度、文件体积、上传和转写状态；可回放、复制结果、导出、重试上传、删除（明确影响范围）。
3. **计算设备**：发现的设备、手动连接、首选节点、在线/离线、可用模型、连接状态与自动上传开关。

关键状态：

- 未录音；录制中；暂停；麦克风权限被拒绝；麦克风被中断；存储不足；录音已安全保存。
- 等待首选设备；节点离线；等待同一 Wi-Fi；上传中（真实进度）；上传中断/重试；节点排队；正在转写；转写完成；失败；节点结果已过期。
- 没有任何计算设备时：录音功能**仍必须可用**，文件本地排队，不强制连接电脑。
- 结果页只读、按语义段落排版，不显示密集时间戳；支持文字选择、复制全文、TXT 和 JSON。
- 上传后不自动删除本地录音。删除前需明确提示；不能误删远端用户已有任务。

与桌面统一：顶部或设置中能查看当前设备与模型，但手机端不照搬桌面侧边栏和模型管理页。

## 5. 录音可靠性（最高优先级）

- 用户手动启动录音后，按各系统规则在锁屏持续工作；iOS 使用后台音频能力，Android 使用合规的麦克风前台服务。
- 实时写入可恢复格式或采用分段录音 + 会话清单；避免整段录音只存 RAM。
- 统一时间基准，记录录音创建时间、时长、采样率、声道、文件格式与会话 ID。
- 处理电话/音频会话中断、音频设备变更、耳机断连、权限撤销、系统资源不足、系统终止或崩溃恢复；未能自动恢复录制时必须明确标记中断，并保留既有音频。
- 优先使用语音友好、系统兼容、能够稳定写盘的格式；在准确率、音质与磁盘占用间权衡。默认不要使用有损压缩至影响 ASR 识别的低码率；协议端明确格式/采样率并必要时转换。
- 录音完成后先完成文件校验与本地数据库事务，再创建上传工作；禁止边写未完成文件边以“完整录音”上传。
- 可以实现用户选择的录音命名和内置回放；不需要波形编辑器。

## 6. 设备发现与模型选择

- 沿用桌面端同一种 mDNS / DNS-SD 服务类型、协议版本和能力字段；iOS Bonjour 和 Android 平台发现调用分别适配。
- 支持 `IP:port` 手动添加；自动发现失败不得影响手动使用。
- 区分设备发现、可连接、可接受任务、忙碌、离线；只显示后端实际返回的状态。
- 首次自动上传前，用户必须**手动选定首选计算节点**；保存设备稳定标识及已知地址，后续只向这个已选节点自动发送。
- 列出该节点已安装且运行后端可用的 ASR 模型，显示适合的语言与可用性；模型由节点管理，手机端不下载模型。
- 节点切换、默认模型切换只影响新任务，不影响已经提交的任务。
- 不允许在节点离线时擅自迁移到另一个节点；用户可以手动重选并重新提交。

## 7. 上传、任务、同步与断线恢复

### 7.1 手机本地记录

每项录音保留：`recording_id`、原始录音本地路径、创建时间、文件大小/时长、`preferred_node_id`、`remote_task_id`、`model_id`、上传偏移/会话、最后事件序号、状态、结果存储路径、最后错误等字段。

### 7.2 推荐状态机

`recording → saved → waiting_for_node → uploading → remote_queued → preparing → transcribing → completed`

其他终态/分支：`upload_failed_retryable`、`transcribe_failed`、`cancelled`、`remote_unavailable`、`result_expired`。录音中断与远程任务失败必须区别对待。

### 7.3 上传与重试

- **先实现前台上传闭环。** 之后完善 iOS 系统后台上传（文件 URLSession）与 Android 可靠延期工作调度。
- 上传使用受控内存的分块处理；支持断点续传、重试、校验和进度，不为大音频一次性构建超大内存字节数组。
- 通过稳定幂等键防止网络重试造成重复任务；必要时扩展节点 API，但保持旧桌面客户端兼容。
- 如节点尚未支持续传，先实现正确的前台上传与失败重试，并明确限制，再扩展协议；不能用伪进度或虚假的续传状态蒙混验收。
- 默认只在用户允许的 Wi-Fi 网络自动上传；蜂窝网络传输需要明确设置并显示数据成本提示，不应默认消耗大量流量。
- 后台操作可能被 OS 延迟、暂停或终止，不能保证离开 App 后立即开始或者一直持续上传。UI 反映真实状态，并允许用户打开 App 手动继续。

### 7.4 节点执行与结果

- 节点拥有执行状态权威；每台节点内部串行，不同节点可并发；客户端仅展示真实节点排队信息。
- 节点断开时不自动改用本机或其他节点；网络恢复先查询原任务状态，避免重新提交。
- 使用事件序号/结果游标恢复增量文本，防重复与缺段；客户端先持久化结果，再向节点确认接收。
- 远程结果保存为结构化 JSON，显示为只读阅读文本；TXT 导出不包含密集时间戳。
- 节点临时音频须等待客户端确认完整接收后清理；长期未确认则按服务端已确定的保留策略处理。手机客户端绝不能删除尚未完成上传的唯一原始录音。
- 结果完成时可提供本地通知，但必须遵循通知权限、系统电量策略与真实后台执行限制。

## 8. 当前无设备配对的安全边界（明确风险，不得忽略）

桌面 LAN V1.1 当前采取「用户主动开启可信局域网节点、暂不配对」策略；移动端必须沿用并诚实呈现其不足。

**关键风险：** mDNS 名称及未认证的设备标识无法抵御局域网中恶意设备冒充；仅“记住 IP/设备名”并非可靠的身份认证。自动上传个人录音尤其敏感。

开发要求：

- 首次上传必须经用户主动选择节点并明确启用该节点自动上传；默认不对所有发现节点广播音频。
- 默认仅在 Wi-Fi/用户允许的网络条件下传输，设置页明确提示「该版本尚无加密身份配对，请仅在可信网络使用」。
- 不在日志记录音频内容、令牌或完整个人转写文本；不暴露任意本地路径、远程执行命令、桌面历史浏览与模型管理 API。
- **不得宣称当前方案提供防冒充、保密或安全认证。** 即便使用传输加密，如未认证节点身份仍无法防止冒充。
- 网络协议预留未来认证扩展点。如果实际隐私风险使“无人值守自动发送录音”不适合默认开放，应默认关闭自动上传，由用户明确开启并确认目标。
- 不得以绕过系统权限、隐藏录音状态等方式达到需求。

## 9. 与桌面端的集成原则

- 尽量复用桌面 LAN Compute V1.1：`discovery`、`capabilities/models`、`upload`、`submit`、`status`、`cancel`、`events/result`。
- 共享协议定义、错误码、API 版本与兼容性测试。可以建立 `packages/protocol` 或类似共享 Schema，避免 Android/iOS 与 Rust 后端字段漂移。
- 服务端如需扩展移动端续传/回执能力，应写 API 迁移文档并增加桌面回归测试。
- 手机远程录音任务进入原节点队列，不新建另一套推理系统，也不在手机端偷偷运行模型。
- 桌面精准应用录音属于桌面功能，不应把 Windows Application Loopback 或 macOS Process Tap 硬移植到 iOS/Android。

## 10. 实施阶段与交付物

### 阶段 A：审计与技术验证

- 核实仓库、LAN API、当前 CI、开发设备、iOS/Android 工具链；决定跨平台框架及原生插件边界。
- 生成 `docs/mobile/architecture-audit.md`、`docs/mobile/implementation-plan.md`、协议兼容表。
- 真机验证 iOS/Android 锁屏录音与本地持久化的基本可行性。

### 阶段 B：录音与录音库

- 实现双平台录音、停止与回放、异常恢复、录音列表、基础 UI。
- 验证 30 分钟及更长录音、锁屏、蓝牙、来电、存储不足和权限关闭场景。

### 阶段 C：LAN 连接与前台闭环

- mDNS 发现、手动 IP、首选节点、远程模型、上传、节点转写、结果展示、TXT/JSON 导出。
- iPhone→Windows、Android→Mac、iPhone→Mac、Android→Windows 至少覆盖不同平台组合；测试条件不足时准确列明。

### 阶段 D：自动上传与断线恢复

- Wi-Fi 条件策略、持久上传队列、后台传输最佳可行实现、幂等提交、任务事件恢复、延迟/失败提示。
- 模拟电脑关机、网络中断、手机锁屏、App 后台/被终止、节点排队、模型缺失等。

## 11. 发布和安装包的真实限制

- **Android：** 可以提供签名的 Beta APK，允许用户下载后按系统提示安装；发布商店则另需相应开发者账号及上架审核。
- **iOS：** 无法在缺少有效 Apple 开发者证书、描述文件与分发途径的情况下，生成“任何人下载即可直接安装”的通用 IPA。优先准备可复现 Xcode 项目/Archive；账号具备条件时使用 TestFlight 或其他 Apple 允许的分发渠道。不得要求 Agent 擅自购买 Apple Developer 会员，也不得声称未签名包可像 APK 那样任意安装。
- 所有发布说明标为 **Early Beta**，披露后台调度限制、节点未配对风险、最低系统版本及已知问题。
- 若仓库已公开，发布前审查源码/历史/截图/配置中是否含 HA 地址、访问令牌、家庭局域网 IP、个人录音、签名私钥及密码；不要把测试素材或个人信息上传到公开仓库。
- GitHub Release 只上传真实产物，不得伪造 iOS/Android 编译状态。
