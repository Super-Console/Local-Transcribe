## 0. 总任务与工作方式

开发可实际安装、可离线使用的跨平台桌面程序 Local Transcribe：用户导入音频或视频，使用自己下载并导入的受支持本地 ASR 模型进行语音转写；逐段展示稳定文字；保存历史；支持 TXT、JSON 导出。GUI、CLI、MCP 使用统一任务核心、统一队列、统一模型生命周期。

Agent 执行要求：

1. 先审计运行环境、工程现状、系统依赖、两平台可行性和模型授权；提出可验证的最小实施方案，再编码。
2. 按本任务书阶段推进，每阶段写自动化测试，运行测试并提交真实结果。不要以 UI 演示替代实际转写。
3. 优先调用成熟开源 ASR/解码方案，不重新训练模型，不自行实现复杂音频编解码器。
4. 对不确定、尚未实测的性能和兼容性明确标注，不得虚构模型支持范围、磁盘/RAM 数据或进度。
5. 允许更换底层引擎或组件，但不得改变已冻结的用户体验；重大技术限制写入风险记录与实现取舍。
6. macOS 和 Windows 必须共用一套核心与 UI 组件，平台特有能力封装适配器；不要假装在未测试的平台完成验收。
7. 完成后输出可运行源码、安装包、CLI、MCP 服务、测试报告、模型兼容矩阵、使用手册及已知限制。

## 1. V1 范围（严格）

### 必须实现

- 本地音频/视频文件导入，拖拽或系统文件选择器，支持批量导入。
- 自行下载的模型本地导入：单文件或文件夹（具体取决于后端）；格式与文件完整性校验；复制到应用管理的模型目录，保留源文件。
- 至少打通一条真实 ASR 端到端链路，并以兼容矩阵明确列出最终实测支持的模型及格式；优先调研 Whisper Turbo、Whisper Large V3、Qwen3-ASR 0.6B / 1.7B。不得把候选模型名称等同于已支持。
- 自动语言检测为默认；在引擎支持时可以手动指定受支持语言。
- 全局串行任务队列，同一时刻最多一个活动推理任务/ASR 模型；排队任务拖拽排序、修改任务模型、移除；运行任务取消；失败后自动继续。
- 稳定文本增量显示，阅读式语义段落，无密集时间戳；结果只读、可选择、可复制。
- SQLite 持久化任务、片段、状态、历史、模型注册信息和恢复必要元数据；TXT / JSON 按需导出。
- 历史列表（日期分组、搜索、筛选、详情、重试与删除记录）。
- GUI、CLI、MCP 通过同一任务服务提交和管理工作，支持与 GUI 同时运行而不重复启动推理引擎。
- macOS/Windows 原生窗口控制、文件对话框、浅深色与键盘基础操作。

### 明确不做

- 云模型 API、在线模型目录/商店、内置模型下载器、自动下载/更新模型。
- 麦克风实时转写、常驻听写、系统输入法、会议实时字幕。
- AI 摘要、翻译、说话人分离、字幕编辑器、内置文本编辑。
- SRT、VTT 等字幕导出（V1 仅 TXT、JSON）。
- 在线账户、同步、遥测/上传媒体、插件市场或复杂项目管理。

## 2. 技术架构与原则

建议而非未经验证的硬性绑定：Rust 核心 + Tauri 2 + Svelte 5/TypeScript 前端 + SQLite + 经验证的 FFmpeg 解码方案。ASR 后端优先评估 sherpa-onnx、whisper.cpp 或成熟封装；不同模型可能需要不同执行后端。比较目标平台打包难度、推理正确性、增量片段支持、CPU/Metal/DirectML/CUDA/其他可用加速的实际情况、许可和资源占用后决策。不得宣称某单一后端天然支持全部候选模型。

架构拆分：

- GUI：页面、用户交互、状态订阅、阅读视图，无独立任务执行器。
- Local Core Service：唯一权威的任务状态、调度队列、进度事件、取消、模型注册与推理生命周期。
- Media Adapter：媒体探测、格式检查、音轨提取、解码与规范化采样；拒绝或处理无音轨文件，确保资源受限。
- ASR Backend Adapters：严格声明可接受的模型布局、量化类型、语言与加速平台；输出稳定片段及可用时间元信息。
- Persistence：SQLite 事务、片段持久化、迁移版本、恢复和搜索索引。
- CLI Client / MCP stdio Server：只通过本地服务 API 执行任务与查询，不重复加载模型。

本地进程通信：macOS 选择受权限保护的 Unix domain socket 或等效方式；Windows 选择带访问控制的 named pipe 或等效方式。确保单实例调度、同用户隔离、接口鉴权/权限校验、防误连接，不在公网监听。GUI 可退出但外部 CLI/MCP 任务仍有合理存活机制；明确守护进程启动、退出、升级、异常恢复策略。空闲卸载模型不代表必须关闭轻量服务进程。

模型管理：同时最多装载一个 ASR 模型；任务开始时按需加载；同模型连续执行复用；切换型号在安全任务边界卸载旧模型；整个共享队列空闲且不存在活动使用方后启动 120 秒计时并卸载。顶部绿色状态点仅表示其旁边被选中的默认模型真正驻留内存，不可代表"已安装"。

## 3. 视觉设计系统

- 产品名称显示为 Local Transcribe；内部包名、应用 ID 由实现确定，统一使用，不要使用历史误称 subscribe。
- 原生风格 + 现代极简；macOS 与 Windows 共用内容布局和组件规范；原生窗口控件、文件/保存对话框、字体与快捷键按平台适配。
- 默认窗口约 900×620 逻辑像素；初拟最小 640×460（须实际检验可用性）；侧栏约 196px；窗口宽度约 780px 以下自动隐藏侧栏，使用滞回避免阈值反复闪烁。
- 用户可主动折叠侧栏；记住主动偏好，窗口恢复变宽时自动折叠不得覆盖该偏好。窄窗下用轻量临时导航或显示/隐藏按钮恢复导航。
- 侧栏：转写 / 历史 / 模型；设置固定底部，不嵌套最近任务列表。绝不加常驻右侧信息栏。
- 页面标题与顶部工具栏低占用；模型默认选择器固定在主工具栏，带加载状态点；队列存在时显示顶部队列入口，打开浮层。
- 浅色、深色、跟随系统三种主题；系统字体，正文基准 15px、行高约 1.6，阅读区域最大宽度约 720px；主内容水平内边距 24–28px，辅助文字 12–13px，控制高度 32–36px，圆角多为 8–10px。全部为可按 DPI/平台校正的设计基线。
- 基本中性色、适度蓝色强调；绿色表示实际已加载/成功，红色仅表示错误或删除警示。不使用夸张玻璃、炫彩渐变、假原生窗口按钮、大面积营销文案。
- 图标轻量一致、完整键盘焦点、屏幕阅读器语义、减少动态效果、文本对比和可访问名称。

## 4. 页面与行为规范

### 4.1 转写：空闲、无模型、导入

- 空闲页中心是细虚线文件拖放区域，低对比度，拖入有效文件时短暂蓝色高亮；不使用大型插画。含「选择文件」按钮；整块区域可点击、可键盘聚焦。
- 导入文件即创建任务并调度，没有"开始转写"按钮。导入中仍可继续拖入文件，后续文件排队。
- 首次没有模型也允许导入媒体，任务标记「等待选择模型」，顶部提示可前往模型页导入；不会强制多页欢迎向导。
- 首次选择有效默认模型后，将其绑定到当时尚未指定模型的等待任务；已绑定特定模型的任务保持不变。绑定和自动开始需要明确可审计的用户操作，不任意给其他任务切换模型。
- 未安装/不可用的已绑定模型显示「等待模型」或对应阻塞原因，不能错误显示为可运行。

### 4.2 转写：运行中与结果

- 任务头展示媒体文件名、该任务实际模型、状态、可信进度、轻量「取消」操作。
- 模型加载中/媒体解码中显示准确的阶段文字。仅后端能给出可信进度时显示百分比；不伪造剩余时长或模型输出百分比。
- 逐段追加稳定识别文本；语义段落、阅读式布局，无气泡、密集时间戳、波形或转写文本内联编辑。原始识别结果与展示层段落独立保存，不得擅自改写内容。
- 默认自动跟随新文字；用户上滚阅读旧内容时停止自动跟随，显示「查看最新」。跨页面返回时按任务恢复阅读锚点、相对位置和自动跟随状态；窗口缩放尽量保证阅读段落不丢失。
- 长文只渲染必要内容/增量更新，复制全文始终从完整记录提取；结果选择、复制、系统标准快捷键必须可用。
- 已完成：复制全文、导出 TXT / JSON、重新导入操作；队列全部结束后停留在最后活动结果。已取消或失败任务有稳定片段时可查看、复制及导出，明确不完整。
- 点击取消立即发出针对特定 task_id 的取消请求，无二次弹窗；取消完成前准确显示「正在取消」；保留稳定片段，自动推进后续任务。

### 4.3 队列浮层

- 顶部轻量图标弹出，点击外部/Esc 关闭；不创建第三栏或独立永久页面。
- 当前执行任务置顶且不可拖动；下方等待任务带拖拽手柄，支持拖动、键盘上移/下移、按任务更改模型、移除。更改默认模型只影响未来新入队任务，不 retroactively 改写已排队任务。
- 运行任务出错：保留错误记录、展示简明原因和「重试」，队列自动继续；不自动无限重试。
- 重试旧记录时维持原指定模型，在其他任务运行时新加入等待队列；成功/失败的结果版本与部分片段不得简单重复拼接。
- 失败任务可在浮层折叠区中显示，并留在历史记录中；失败不计入等待任务数。
- 调度策略：等待列表尊重用户排列，但调度器可暂时跳过缺少模型/不兼容等未就绪任务，选择最靠前的可执行任务；不能暗中改变可见排序，也不能抢占已经运行的任务。未就绪任务一旦恢复可运行，按当时队列及安全边界重新参与调度。
- 任务来源 GUI/CLI/MCP 统一排队。对外部拥有者的任务，控制权限和取消行为必须明确，避免 GUI 意外取消外部任务。

### 4.4 历史页与详情页

- 已结束任务（完成/取消/失败）按本地日期分组（今天、昨天、日期），默认按最近任务活动时间倒序；紧凑文件行：名称、日期、时长（若可获取）、状态。状态不能只靠颜色表示。
- 搜索文件名和正文。建议 SQLite FTS5（验证中文分词效果，必要时选择可维护的索引策略）；搜索不得每输入一字阻塞 UI 扫描全部文本。支持状态筛选。
- 历史详情在主内容区域内打开，提供返回、稳定文本、复制/导出、异常说明、允许重试。返回列表保持搜索条件、筛选、滚动位置。
- 切换历史与转写页面不暂停后台任务。用户停留在历史详情时，队列进展不得强制拉回转写页面；点击「转写」应显示当前活动任务，若无活动任务显示最后结果或空闲页。
- 删除记录须确认；删除历史结构化数据和本应用保存的转写文本，不得删除原始媒体或用户已导出文件。

### 4.5 模型页与导入流程

- 没有在线可下载列表、模型商店和内置下载按钮。模型页只展示用户已经导入/登记的本地模型；主操作「导入模型」。空状态显示清楚的导入指引。
- 通过系统对话框选择受支持的文件/文件夹；先验证格式、缺失必需文件、版本、后端兼容性、架构/运行平台、许可风险（许可说明为开发核验，不强制所有模型联网）；验证不过明确给出原因。
- 默认复制到应用管理的模型目录，源下载文件保留。通过临时目录复制、验证、原子切换/登记，防止部分拷贝出现在可用列表。处理重复导入、重名、空间不足、权限不足、失败清理和应用退出恢复。
- 模型列表区分：可用、已安装未加载、正在加载、已加载、不兼容、失效等；绿色小点仅代表实际加载到内存，灰点不能暗示已加载。顶部默认模型切换只改变新任务默认值，不立刻加载。
- 详情显示准确的模型来源/兼容后端、语言支持、安装目录、实际磁盘占用、可用时的实测内存指标；未测量的内存资源标注「未知」或「估计」，不可硬编码演示数字。
- 设置中可查看/打开/更改模型存储目录；迁移实行空间预检、复制校验、数据库事务式切换、失败回滚；不可默默删除旧路径文件。
- 正在运行或被排队任务依赖的模型禁止直接删除；必要时明确阻塞原因或要求先更改任务模型。删除前确认只删除应用管理的模型副本，不删除用户原始下载文件。
- 须给用户提供受支持模型格式的离线导入说明，可链接到开发文档，不维护远程模型列表。用户可以自行从合法来源获取模型。

### 4.6 设置页

一个主页面内五组，无多层设置迷宫：

1. 通用：系统/浅色/深色主题，启动与窗口偏好。
2. 转写：默认模型（亦可通过顶栏改）、默认语言（自动检测）、模型空闲卸载时间（默认 2 分钟，若 V1 只做固定值也须在 UI 说明清楚）。
3. 存储：模型管理目录路径、修改目录与安全迁移、打开文件夹、历史数据路径与占用信息；不得轻率迁移已有历史数据。
4. 集成：CLI 与 MCP 本地可用状态、路径/配置示例、复制调用说明、服务启动与故障排查。无需云账户。
5. 关于：产品名称、版本、开源许可、第三方组件版权、诊断日志位置。

所有设置均以实际实现能力为准，不做无效装饰性开关。

### 4.7 系统对话框与退出/恢复

- 无活跃任务时正常关闭窗口。存在当前任务时，提供「继续后台处理」与「停止任务并退出」两种清晰操作；退出策略须区分 GUI 任务与由 CLI/MCP 启动的共享任务，避免 GUI 关闭误杀外部任务。
- 意外崩溃/机器重启后，下次 GUI 打开询问是否恢复未完成队列；用户未确认前不得悄悄分配大量内存运行模型；支持稍后处理。已保存稳定片段保留，恢复执行不得重复片段或污染原始记录。
- 模型导入失败、删除模型、删除历史等提示使用准确中文，不以日志堆栈代替用户可理解的说明。必要时提供展开技术详情。

## 5. TXT / JSON 数据契约

- 内部结果必须保留稳定片段结构、生成顺序、原始文本、可用时的 start_ms / end_ms、模型标识、语言信息、任务状态和错误信息。
- TXT：以自然段落和合适换行组织全文；不默认输出逐句时间戳、调试日志或系统元数据。对于部分结果，导出前 UI 必须明确提示其不完整。
- JSON：设定稳定版本字段如 `schema_version: "1.0"`；建议包含 task_id、source（文件基本信息，注意可选择是否避免暴露绝对隐私路径）、status、model、language、text、segments、created_at、completed_at、is_partial、error。字段定义与可空规则须在文档固定，MCP/CLI/GUI 一致。
- 用户触发导出时使用原生保存对话框；导出失败不改变任务完成状态；导出写临时文件再安全替换，避免写出半截文件。
- 内部自动持久化，不等于每次完成都自动生成外部 TXT/JSON 文件。

## 6. CLI 和 MCP 接口要求

### CLI（建议可用功能）

- `local-transcribe status`
- `local-transcribe models list|import|info`
- `local-transcribe jobs add <file> [--model MODEL_ID] [--language LANG]`
- `local-transcribe jobs list|show|cancel|retry|reorder`
- `local-transcribe export <task_id> --format txt|json --output <path>`

命令名称、参数可在正式实现时调整，但必须稳定、可脚本调用、输出机器可解析 JSON 模式，退出码明确，包含 `--help`；不得为了 CLI 启动第二套独立推理引擎。

### MCP（stdio 服务端）

至少覆盖模型列表/查询、导入可用模型（如安全权限允许）、提交任务、查询状态/结果、列队、取消/重试、导出接口；使用 JSON schema 明确工具输入输出、错误码与异步任务 ID。文件路径的安全边界、敏感信息、同用户访问控制及资源限制必须有测试。不得将长期模型推理放在易超时的同步 MCP 调用中；提交返回 ID，客户端轮询查询或通过允许的事件机制获取结果。

使用体验：设置 → 集成显示 MCP 配置样例、CLI 位置、连接状态、复制按钮及最小示例；不使用无意义的"启用云服务"开关。

## 7. 性能、稳定性与安全

- 软件安装体积不包括默认下载模型；无模型时仍能打开/浏览/导入等待任务。
- 空闲时不无故加载 ASR 模型或持续高 CPU 轮询；共享核心按需装载，120 秒空闲卸载。
- 长篇记录（至少数万至十万字）滚动、搜索、复制和增量展示保持顺畅；按段落定位且不破坏文本选择。
- 批量文件串行处理，无跨平台不同 UI 行为导致的任务重复执行；状态更新与持久化须抗竞态。
- 文件格式与模型文件均视为不可信输入，限制输入规模、解析超时和异常资源占用；解码组件及时更新，记录第三方许可义务。
- 不在日志中默认记录完整音频、文本或用户隐私路径；日志可供诊断、可清理。
- 无互联网依赖才能正常转写；不对外监听服务；除用户自己管理模型下载外，不需要在线功能。
- 实测 macOS（Apple Silicon、如可覆盖 Intel 则记录）和 Windows 的 CPU/可用 GPU 执行情况；性能指标附环境、模型、量化、音频长度与测量方法。

## 9. 必须通过的验收场景

1. 零模型启动：离线打开应用，导入两份媒体，均出现「等待选择模型」；随后导入兼容模型并选择，任务自动串行运行。
2. 导入安全：模型复制期间中止/空间不足/重复导入，源文件保持完整，未成功复制的模型不显示"可用"。
3. 任务模型快照：A/B 排队后改变顶部默认模型，不修改 A/B 的指定模型；修改 B 的模型只影响 B。
4. 跳过不可运行任务：A 等待缺失模型、B 可运行，B 可先执行；A 仍保持可见顺序与等待状态，模型就绪后可继续调度。
5. 串行与驻留：全系统同时一个推理任务、一份加载模型；同模型任务复用；全局队列空闲 120 秒后卸载并使绿点消失。
6. 取消与失败：运行中取消不询问，保留稳定片段，后续继续；单任务解码失败保留错误，后续继续，手动重试不重复拼接旧片段。
7. 转写与历史独立：在历史详情阅读时后台任务完成，不强行跳转；返回转写展示当前活动任务。
8. 阅读状态：阅读较早段落时持续生成新段落，滚动位置不跳动；跨页面与窗口宽度变化恢复阅读锚点。
9. 导出：TXT 阅读式、JSON 带结构化段落和可用时间戳；已取消/失败部分结果明确标记不完整。
10. 历史：按本地日期分组、文件名及正文搜索、筛选、打开详情；删除记录不会删原音视频和已导出文件。
11. 关闭/恢复：有活动 GUI 任务时选择继续后台/停止退出生效；CLI/MCP 活动任务不被 GUI 关闭误杀；强杀后下次启动需要用户批准恢复。
12. 多客户端：GUI + CLI + MCP 并发操作不会创建两个推理服务或并发加载两个模型，状态一致。
13. 跨平台：macOS/Windows 窗口控制、系统文件对话框、键盘操作、深浅色/跟随系统、窄窗折叠和文本复制均实际验证。
14. 性能与安全：长文本稳定浏览，空闲时模型真正释放；日志不默认泄露音频正文，非法模型文件/损坏视频不会造成不可恢复崩溃。

## 11. 优先风险及冲突处理规则

**R1：不同模型不等于统一文件格式**
Whisper 与 Qwen3-ASR 可能需要不同前处理、运行后端和模型转换产物。"选择任何下载模型即可导入"不成立。导入器必须给出明确支持格式，必要时仅支持指定量化/导出版本；开发先行 P0 验证。

**R2：跳过未就绪任务与拖拽顺序**
区分"用户可见优先顺序"和"下一项可运行任务选择"；跳过不重排，模型恢复可用后按最新优先级处理。

**R3：关闭 GUI 与共享服务存活**
如果推理只存在于 Tauri 主进程，关闭 GUI 无法真正后台继续，而且 MCP/CLI 可能重复加载。必须在 P0 验证独立本地任务服务与授权 IPC；未打通就不能宣称完成后台/MCP 能力。

**R4：恢复队列与部分结果**
意外关闭可能留下半段文本、部分复制模型或未完成导出。采用事务、任务/片段唯一 ID、幂等恢复、完成边界；恢复前必须征得用户同意。

**R5：模型目录迁移和删除**
目录迁移与运行中的模型/队列使用可能竞态。需对运行、导入、迁移、删除实施互斥/租约或安全等待；失败回滚，不产生数据库与磁盘不一致。

**R6：高效全文搜索与虚拟化选择**
SQLite FTS5 中文搜索的 tokenization 需验证；虚拟化文本不能破坏鼠标选择、屏幕阅读器或整篇复制。必要时先优化增量 DOM 再逐步引入可访问虚拟化。

**R7：进度准确性**
基于音频已处理时长的进度可能是估算值，须明确口径；在未知时显示"正在识别"而不是模拟 68% 或剩余分钟。

**R8：第三方许可、平台构建与驱动依赖**
FFmpeg、ASR 引擎、模型权重许可及加速运行库可限制分发。发布前检查版权、构建方式、平台签名/权限；不得把测试通过的某一设备当成跨平台保证。
