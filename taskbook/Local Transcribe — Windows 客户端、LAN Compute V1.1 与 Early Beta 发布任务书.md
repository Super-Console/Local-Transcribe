## 2. 不可更改的 V1 产品和 UI 基线

项目为 **Local Transcribe**：macOS / Windows 本地音视频文件转写软件。用户自行下载支持的模型，导入软件后复制到应用管理目录；**不做在线模型商店/下载器**。应用兼容的是经明确适配、验证过的模型格式，绝不能对“所有 Hugging Face 模型均可运行”做虚假承诺。

- 设计：Apple 原生气质 + Raycast 式克制工具感；轻量、低装饰、不做 SaaS 仪表盘。浅/深色主题，默认随系统；macOS 和 Windows 共享一套布局，采用各平台的原生窗口控件、文件对话框和键盘习惯。
- 主窗口：默认约 900×620 逻辑像素，左侧约 196px 的“转写 / 历史 / 模型”导航、“设置”置底，侧栏可手动隐藏并在窄窗口自动隐藏。内容区上方有模型选择器；增加 LAN 后，在其左边放计算设备选择器。
- 导入区：安静的细虚线边框；拖放或选择媒体后自动入队，不设额外“开始转写”按钮。
- 转写结果：语义分段、阅读式排版、默认无密集时间戳、只读但可选择和复制；仅 TXT / JSON 导出。长文本需要增量渲染，阅读位置与自动跟随状态按任务维持。
- 队列：顶部入口弹出浮层；当前执行任务固定顶部；等待任务支持排序、移除和更换模型；失败任务保留错误并允许单独重试，队列继续；取消不二次确认，保留稳定的部分结果。
- 模型：用户导入单文件或文件夹 → 格式验证 → 复制到应用私有模型目录 → 可选择；保留源文件；支持安全迁移模型目录；真实已加载的模型才显示绿色点。运行节点无工作后，默认约两分钟卸载模型；一个节点一次执行一个 ASR 任务。
- 历史：按日期分组的紧凑列表、文件名和正文搜索、结果阅读、复制、导出、重试、删除记录（不删除原始媒体）；默认保留直至用户手动删除。
- 设置：通用、转写、存储、集成、关于；集成包含 CLI/MCP 指南和 LAN 设置。
- 任务状态通过 Rust 或已有任务核心统一存取，GUI 不伪造结果、状态、进度和加载情况。
- 不擅自增加云 ASR、总结、翻译、实时麦克风听写、字幕编辑器、账户系统等 V1 范围之外功能。

如仓库现状和以上设计之间存在差异，优先保证现有稳定功能不回退；将未实现项标记清楚，逐步补齐，而不是通过重写整个项目掩盖差异。

## 3. 第一优先级：开发真正可用的 Windows 客户端

### 3.1 功能目标

Windows 版本必须成为 Local Transcribe 的一等公民，而不是一张跨平台 UI 截图：

- 真正启动、完整渲染 UI、使用原生 Windows 窗口标题栏与文件对话框、支持系统主题、高 DPI、鼠标/键盘操作。
- 能从 Windows 本地文件选择器或拖放区导入常见音频和视频；可解码音轨并创建任务。
- 能导入**已通过验证的真实模型**并在 Windows 上实际执行语音识别。至少选择仓库当前真实支持、依赖可管理的一个模型家族作为 Windows 首发验收模型；其他未验证模型明确标注暂不支持。
- 能显示真实转写结果、稳定分段、可信进度、历史、TXT/JSON 导出、取消与失败继续；保持原始文件不受损。
- 支持模型存储在 Windows 用户应用数据目录（使用合适平台 API 定位，禁止写入 Program Files 或安装包内）；复制导入时原子化校验，避免模型损坏。
- 跨 GUI / CLI / MCP 共享任务核心（若 CLI/MCP 尚未实现，按现状落地可运行的最小集成并如实记录限制），避免重复加载推理模型。
- 处理中文路径、包含空格的文件名、长路径、文件锁、无管理员权限安装、用户目录权限、Windows Defender 和防火墙的正常行为。

1. 检查 Tauri 及其依赖版本支持的 Windows 打包方式。推荐至少交付 **Windows x64 的 `.msi` 或用户友好的 `.exe` 安装器**；条件允许交付两种。若目标机器及依赖支持 Windows ARM64，再增加 ARM64；不能假设可用。

3. 对一个干净或尽可能干净的 Windows 用户环境进行**真实安装、打开、导入模型、转写、导出、卸载**的端到端测试。
4. 提供 README 中的 Windows 安装说明。未提供有效代码签名时，明确告知 Early Beta 可能出现 SmartScreen 等提示；不要伪称已经签名或“完全无警告”。

### 3.3 目标 Windows PC 处于关机状态：通过 Home Assistant 唤醒

目标环境中，用户的 Windows PC **默认关机**。请按以下优先顺序操作：

1. 查找工作环境已授权的 Home Assistant API / MCP / 集成配置（不得将 token 输出到日志或提交仓库）。列出能够明确识别为**目标 Windows 主机的唤醒开关/脚本/按钮**。

## 4. 第二优先级：LAN Compute Node V1.1 跨平台局域网推理

### 4.1 核心产品行为（全部已确认）

- 同一套 Local Transcribe 安装在 macOS / Windows 上，**每台设备均可作为客户端和/或计算节点**。
- 节点功能默认关闭，用户在设置中主动启用；记住设置偏好，不默认开机自启。已启用节点时关闭 GUI 可继续后台服务；明确退出应用才停机。
- 设备通过开放标准 **mDNS / DNS-SD** 互相发现（并非 Apple 独占 Bonjour），手动 `IP:端口` 作为备用方式；支持 Mac→Windows、Windows→Mac、同系统设备间组合。
- **V1.1 暂不实现配对或用户认证**。仅限用户主动启用的可信家庭局域网。明确提示安全限制。不要宣称不配对也能保障只有提交者看到结果。
- 顶部工具栏先选择“这台电脑 / 可用计算节点”，再选择**对应节点上已导入且真正可运行**的模型；模型状态点表示所选节点的真实加载状态。
- 提交远程任务时，当前任务保存不可变的目标节点 ID 和具体模型 ID；切换默认设备和模型不影响已提交任务。节点离线不自动切换成本机或其他节点。
- 客户端提取并规范化媒体音轨，使用分块传输；不上传完整 4K 视频。禁止用极端有损压缩降低识别质量；格式/采样率按后端能力协商，优先无损或经过验证的音频传输形式。
- 每个计算节点**同一时间只运行一个 ASR 任务**，多个客户端共享此节点的任务队列；不同计算节点可以并行执行各自任务。
- 客户端断网/睡眠不取消节点任务；重新连接查询任务状态，获取未收到的稳定转写片段；避免重复上传/重复推理/重复拼接文字。
- 客户端保存最终历史；节点独立保存必要任务状态、音频临时文件和结果缓存；只有确认结果已经在客户端持久化后，才提前清理相应临时数据。未确认接收的断线任务保留有限期限，然后明确标注过期。
- CLI 和 MCP 也复用同一套本地/远程任务提交核心。

### 4.2 推荐协议与模块分工

- **发现层**：Rust 跨平台 mDNS / DNS-SD；使用独立的服务类型和协议版本；广播只暴露最小非敏感信息，例如节点展示名、协议版本、端口及稳定节点标识，不广播绝对文件路径、用户名、密钥或模型目录。
- **控制层**：HTTP JSON API（如 `GET /v1/capabilities`、`GET /v1/models`、`POST /v1/tasks`、`GET /v1/tasks/{id}`、`POST /v1/tasks/{id}/cancel`）；这些是建议接口，落地前写 OpenAPI 或等价协议文档。
- **事件层**：SSE 或当前项目技术栈更合适的可恢复事件流，包含 `task_id`、`event_id/seq`、状态、时间和稳定片段，支持 `Last-Event-ID` 或等价游标恢复。
- **音频层**：按块上传（有总大小/单块大小/时间限制、校验、幂等上传会话及磁盘额度）；避免整个音频一次性读入内存。
- **状态层**：客户端任务 ID 和节点任务 ID 映射；幂等提交键；每个结果片段有稳定唯一 ID 与序号。上传、排队、准备、推理、完成、失败、取消、结果过期分别表示；任何进度必须基于真实事件。
- **计算层**：节点使用现有统一 ASR 模型适配与队列，不能再维护第二套 ASR 核心。节点 CPU/GPU/模型只在节点本地运行。
- **部署层**：LAN HTTP 服务绑定用户选择的可信网络接口；在 Windows 上仅引导设置必要的入站规则，优先私有网络配置，不关闭整个防火墙；macOS 尊重本地网络权限。

### 4.3 多客户端队列与排序冲突的处理

- **节点队列是执行事实的权威来源**；客户端队列只反映该客户端提交的任务与节点返回的实际状态。
- V1 原有的拖动排序在 LAN 场景不能直接改写其他客户端的任务。只允许对自己提交且尚未运行的任务请求重排；节点验证是否可重排并返回真实位置；如果无法在现有协议内可靠实现，则禁用远程拖排并显示“远程队列顺序由计算节点决定”，不能伪装成功。
- 调度以每节点串行为核心，客户端 UI 明确显示“等待计算节点”；一个节点正在执行时，其他客户端不能使它中断。
- 本地 V1 已确定：模型未就绪的任务可以被可运行任务暂时越过；远程实现应采用同一显式调度规则并在节点侧测试，绝不能静默修改用户排序配置。

### 4.4 断线、退出与取消

- 客户端断线：计算节点继续；客户端重连之后通过保存的节点 ID、任务 ID、事件游标获取当前状态和遗漏结果。
- 节点进程重启：明确区分“客户端断线可续接”与“模型推理真正断点继续”；若推理过程无法保存模型状态，则可重新处理该任务、确保最终结果不重复，并向客户端明确显示。
- 请求超时：先查询节点上是否已受理相同幂等键，避免盲目重发。
- 取消：针对精确 task ID，确认节点已经停止对应的推理后才标记取消，保留稳定结果；不能误取消下一任务。
- 关闭 GUI：已启用节点时服务保持运行，并提供系统托盘/菜单栏管理入口及退出功能。既有“关闭 GUI 但有活动本地任务时询问”的策略应与服务持续运行合并设计，避免冲突。
- 明确退出：停止接收新任务；有正在执行任务时，以清晰策略处理（默认提示是否结束任务并退出；在无人值守情况下使用安全停止并保留部分结果）；释放监听端口、模型进程及锁。后台服务不得变成不可控制的孤儿进程。

### 4.5 临时文件安全与清理

- 节点维护专用临时目录，设置配额、任务隔离目录、过期清理策略。音频上传/识别结果不落在公开可访问的目录。
- 成功收到客户端**持久化确认**后，可及时删除原始上传音频；短期保留必要事件与终态以支持重连。
- 长期离线数据以明确的 TTL 过期，例如默认 7 天（仅工程默认值，可在配置中修改），过期状态可查询；不可在未提示的情况下把过期结果报告为成功恢复。
- 不向局域网开放任意文件系统 API、任意命令执行 API、模型删除/导入远程管理、GitHub/HA 管理能力。

### 4.6 不配对的安全限制：必须诚实告知

无配对和认证意味着同一可达网络中的其他设备可能发起转写任务、消耗资源、查询或干预任务；随机 task ID 不是完整的访问控制。为降低风险，实施默认关闭、用户主动启用、可信网卡绑定、严格大小/时长/并发/存储配额、请求限流以及可立即停用服务；但**不得把这些替代措施描述成完整认证或保密保证**。为未来的认证层保留兼容扩展点，不在本次强行加入配对 UX。

## 5. GUI / CLI / MCP 的 LAN 集成要求

- 转写页顶部：设备选择器 → 当前设备上的模型选择器。默认“这台电脑”；当节点被发现，显示可识别名称与在线/离线/不可用状态；手动添加 IP 是显式备用入口。
- 设置 → 集成或局域网计算：开启/关闭“作为计算节点”，监听地址/端口、节点展示名、设备发现状态、当前任务数、可信网络警告、复制连接地址、查看错误。用户启用后关 GUI 不自动停服务。
- 模型管理页只管理本机导入的模型，不提供远程模型文件管理；远程模型目录只用于展示可用模型能力。
- 远程任务在任务信息中显示目标设备与当前队列状态；断线后显示“连接中断，计算节点可能仍在工作”，不能直接标记失败。
- CLI / MCP 为本地/远程执行目标提供同等能力（枚举节点、枚举模型、提交任务、查询进度、取消、获取结果），避免重复实现。敏感参数不输出到面向用户的共享日志。
- 文案中不能假称已经配对、加密或拥有专属访问权限。

## 6. 自动化测试与真实设备验收

### 6.1 Windows 客户端必测

- 在真正 Windows 设备：从安装器安装 → 启动 → 导入真实支持模型 → 导入短音频和视频 → 获得可理解的真实文字 → 查看历史 → 复制 → 导出 TXT/JSON → 取消任务 → 再次打开仍可查看结果 → 卸载。
- 验证：中文路径、非 ASCII 文件名、权限受限的普通用户、无网络使用转写、模型不存在、错误音频、无模型状态、深浅色、窗口缩放、文件拖入。
- 测量：空闲资源、模型加载后内存、2 分钟闲置卸载、后台服务内存、关闭时进程生命周期；保留真实数值，不编造性能指标。

### 6.2 LAN 必测

- Mac → Windows、Windows → Mac；如设备条件允许，再测 Mac → Mac、Windows → Windows。
- 自动发现；手动 IP；Windows 防火墙私有网络入站；路由器多播失败的合理提示。
- 两个客户端同时向一个节点提交 → 节点串行；两个节点并行 → 不互相阻塞。
- 长视频只传音轨；上传中途断线并恢复；转写中途断线并恢复；客户端休眠；节点停止/重启；取消与断线竞争；任务幂等。
- 客户端持久化后节点临时音频清理，未确认接收前不得提前清除；TTL 过期有明确状态。
- 关闭节点窗口但保持后台可用；从托盘明确退出后端口释放。

### 6.3 自动化证据

- 单元测试：任务状态机、事件去重、模型能力映射、路径/上传校验、清理规则。
- 集成测试：两个模拟客户端共享同一节点队列；分块上传/续传；端点错误和超时；异常退出。
- UI 测试或操作录屏/真实截图：空闲页、转写中、完成结果、历史、模型导入、设置、LAN 节点选择、断线状态、深浅色。
- 测试结果写入 `docs/testing/early-beta-test-report.md`，注明 OS 构建版本、设备、日期、命令、通过/失败与截图文件位置。**没有真实设备或真实模型时必须标记未验证，不得代填通过。**

## 7. GitHub 双语公开展示与 Early Beta 发行

### 7.1 仓库确认和发布顺序

1. 验证 `git remote -v`、当前登录用户、仓库 owner/repo 与现有 Private 状态，确认唯一正确的 Local Transcribe 仓库。保留回滚用 tag / 已知可用提交记录。
2. 合并/推送已通过测试的代码。配置合理 `.gitignore`，避免提交模型权重、录音、转写结果、构建缓存、Home Assistant 凭据或本地机器配置。
3. **在改变 Private → Public 之前运行严格的秘密与隐私审查**：扫描当前文件、完整 Git 历史、LFS、历史提交、CI 配置、Issue/PR 中可能公开的内容；特别注意 API token、SSH key、HA token、个人数据、内部 IP、录音及个人文件路径。若发现泄密，先真正清除历史并轮换受影响凭据（若无对应权限，阻止公开操作，记录原因）。公开后历史也可能对所有人可见。
4. 检查仓库中所有需要公开的代码及第三方依赖许可是否允许相应发布；如果没有合适的开源许可证，不能擅自宣称它是开源项目或自作主张选择许可证；README 可如实写源码公开/许可证待定（若需要完整开源发布则记录 blocker）。
5. 前四项通过后，在用户已明确授权范围内把**正确仓库**由 Private 变更为 Public；验证匿名访问可读。
6. 创建 pre-release，例如 `v0.1.0-beta.1`，标题采用 **`Local Transcribe v0.1.0 Early Beta`**；设置 GitHub Release **Pre-release**，不标记 Stable。
7. 上传真实构建的、可直接安装的二进制和校验信息；Release 描述写明安装要求、真实功能、已知问题和反馈入口，英文在前，中文在后。

### 7.2 GitHub README 要求（英文在前，中文在后）

README 首页必须直观、干净，包含：

1. **英文部分先出现**：项目名称、一句话介绍、Early Beta 提示、macOS/Windows 支持、最重要能力、直达 Release 下载链接、安装方法、模型导入限制、LAN Compute 使用说明、安全提示、CLI/MCP 使用方式、构建方法、已知限制、贡献/Issue、许可证现状。
2. **中文部分在英文之后**：相同内容的自然中文翻译，不要粗糙机翻，不与英文部分矛盾。可在顶部提供跳转到 English / 简体中文 的目录锚点，但正文顺序必须英文先中文后。
3. **真实应用截图**：至少包含真实运行的 Windows 主窗口、正在转写/完成结果、模型页面、局域网设备选择；条件允许增加 macOS 截图、深色模式。图片使用相同设计语言，合理裁切和压缩，存放 `docs/assets/screenshots/` 并在 README 中相对路径嵌入。**不要把 AI 生成的概念图冒充软件真实截图**；如果概念图需要展示，单独标注 Concept / 概念设计。
4. README 清楚说明没有内置模型下载器，需要用户自行下载已支持格式的模型后导入；列出**实测可用**模型家族、操作系统及后端，不夸大 FireRed/Qwen 等尚未验证的支持情况。
5. Release 和 README 的下载链接要指向对应真实安装资产，而不是指向源码 zip 或构建日志。

可按需要拆出 `README.zh-CN.md`、`docs/architecture/`、`docs/troubleshooting/`，但主 README 仍必须可直接看到**英文在前、中文在后**的关键内容。

### 7.3 GitHub Release 资产清单

至少在条件允许且实测通过时交付：

- `Local-Transcribe-<version>-Windows-x64.msi` **或** `.exe`（能直接双击安装；若两种都稳定可同时提供）。
- `Local-Transcribe-<version>-macOS-arm64.dmg`（真实可用时）；如支持再增加 macOS x64 构建。
- 统一命名，文件中不得夹带模型权重、私人录音或敏感路径。
- `SHA256SUMS.txt` 或等价校验清单。
- 安装包大小与依赖说明、平台架构、签名/公证现状、Early Beta 风险说明。

Windows / macOS 因未签名而触发系统安全提示时，应诚实记录并说明，不要绕过安全机制。**某平台构建未通过验收时，不能发布误导用户的安装包**；可以先发布经验证的平台，并明确说明另一平台仍在开发中，同时记录与用户目标的差距。

### 7.4 CI / 可复现发布

尽可能增加 GitHub Actions 等 CI（Windows 与 macOS runner）执行依赖安装、lint、单元测试、构建和打包。适当固定版本；不将私密 token 硬编码到工作流。真正发布资产只能来自已通过测试的构建。CI 虚拟机上的构建成功不等于物理 GPU/模型兼容性已验证。

**Gate 5：不得以“构建命令执行过”代替用户实际安装验证。**

## 9. 工程质量、回归和性能要求

- 不破坏已有本地模型数据、历史转写记录、原始音视频或已安装环境。
- 文件操作采用安全路径、临时文件、校验后原子提交；处理网络上传大小/路径穿越/目录清理。
- 长音视频分块流式处理，避免把整个媒体或整个历史结果一次性加载到内存；不能将网络流畅性建立在无限缓存上。
- 确保真实模型退出后资源可以释放，节点有活动任务时不误执行 120 秒模型空闲卸载。
- 所有模型兼容性、进度和内存数据只能基于实测或明确标记为估算。
- Windows/macOS 遵循系统休眠、DPI、权限和后台行为，不刻意隐藏系统安全弹窗。
- UI 不能因断网把远程任务错误标为失败；错误必须能向用户解释并可恢复。
- 尽可能通过清晰模块边界和接口契约减小后续接入真正配对/认证的成本。
