# Local Transcribe — 五项增强功能跨平台开发任务书 V1.0

> **交付对象**：具有仓库访问、编译测试与必要设备访问权限的 AI Coding Agent（OpenCode / Codex 等）  
> **性质**：可直接执行的追加开发任务书；不是功能建议、概念设计或仅 UI 原型  
> **产品**：Local Transcribe（名称拼写和空格必须一致）  
> **覆盖平台**：macOS、Windows、iOS、Android（功能适用范围详见各节）  
> **核心新增功能**：①文字与音频同步回放；④SRT/VTT 字幕导出；⑤词汇表与术语纠错；⑦手机录音时间标记；⑩任务诊断与性能统计  
> **执行策略**：接续现有 Windows/LAN、Windows 录音、Mobile、BYOK AI 任务；先复核实际实现再集成，采用无人值守的自主技术决策与排障流程。  
> **版本建议**：Local Transcribe Enhanced Early Beta（具体语义版本号按仓库现状决定，勿擅自覆盖已发布版本）。

## 0. 最重要的执行约束：只做这五项

用户本次**明确选择**以下五项，不要因为原始功能列表还列有其他候选，就擅自扩展成新一轮“大而全”开发：

1. **文字与音频同步回放**：点击文字跳到对应音频，播放时可高亮对应文本；支持已有音频/视频和录制文件。
2. **SRT / WebVTT 字幕导出**：从可靠的转写时间戳生成字幕；无可靠时间戳时不得伪造。
3. **词汇表及术语纠错**：用户维护词条，支持转写结果的非破坏性规范化纠错；识别前热词仅针对确实支持的模型实现。
4. **手机录音时间标记**：iOS/Android 正在录音时单击添加书签，录完后能关联到播放时间与转写片段。
5. **任务诊断与性能统计**：让用户查看真实任务耗时、设备、模型、实时倍率 RTF、可获得的内存指标及错误诊断，杜绝虚构数据。

**非目标**：本任务不新增截图/PPT 联动、说话人自动识别模型、跨课程向量检索、自动工作流、字幕时间轴高级编辑器、音视频剪辑器、在线模型商店、云账号和在线同步服务器。不要重写 ASR 引擎、录音引擎或 BYOK AI 功能。

**前置顺序**：原则上应在既有 Windows 与 LAN Compute 基础、移动录音及主要转写流程可正常运行后再开发。本任务书可以提前交给 Agent 排队，但不得抢占已在开发的核心路径。若前置模块部分尚缺，只处理本任务必要的兼容性缺口，不自行声称其他大型任务已经验收。

## 2. 全局技术原则与依赖关系

### 2.1 先理解原有产品架构

桌面端预计为 Tauri 2 + Svelte 5 / TypeScript + Rust 核心，使用 SQLite、本地模型适配器、CLI/MCP、LAN Compute 节点。移动端以现有仓库最终采用的技术栈为准（Flutter / RN / 原生）；**不要为了统一技术栈重写已完成的移动端**。

功能共用一个领域模型，而非桌面和手机各自发明互不兼容的数据结构。建议存在以下逻辑实体（具体名称按现有设计调整）：

- `Recording`：一个录音会话、原始媒体、来源平台及可选多个轨道；
- `MediaTrack`：媒体轨道标识、来源、时基、起止时刻和实际可播放媒体定位；
- `Transcript`：一次 ASR 推理得到的原始结果、模型、源轨道、转写版本；
- `TranscriptSegment`：稳定段落 ID、原始文本、开始和结束时间、时间戳粒度/可靠性等级；
- `TranscriptRevision`：人工校对或术语规则应用后的非破坏性文字版本；
- `RecordingMarker`：某个录音会话与轨道/全局时间轴上的用户标记；
- `TermDictionary` / `TermEntry`：用户词典、作用范围、词条来源、纠错策略；
- `TaskDiagnostics`：与任务和运行设备关联的测量数据及指标来源。

新增表/字段必须迁移旧数据，数据库迁移有版本号和回滚/恢复策略。升级后已有历史转写和录音不能丢失。

### 2.2 时间轴统一约定（五项功能的共同根基）

**绝对不要依赖 UI 显示文本位置来推断音频时间。**

- **规范时间**：每份源媒体或轨道的本地媒体时间 `time_ms`（或更高精度整数 tick），起点为可播放音频的 0，不能用本地时间、电脑当前时钟或网络到达时刻充当媒体偏移。
- **跨轨道**：一段录音会话具有公共会话时间轴；每条轨道保留其与会话时间轴的 offset、暂停/丢帧/恢复信息和采样率转换映射。绝不假定多个设备采样时钟永不漂移。
- **合法片段**：`start_ms >= 0`，`end_ms > start_ms`，且不超过可确认媒体时长；若 ASR 输出了边界异常，修正/剔除时记录审计，而不是悄悄制造假精度。
- **时间戳等级**：明确区分“词级可信”“片段级可信”“只有粗略分段”“无时间戳/未知”。阅读回放和字幕能力根据等级降级。
- **版本关联**：每条文本片段使用稳定 `segment_id` 与源轨道/原始时间范围关联，校对、术语替换、UI 自动换行不能使时间引用失效。
- **来源独立**：录音本体、ASR 原始文本、用户校对文本、AI 生成内容分别保存；不得让 AI 文本覆盖原始 ASR 的时间信息。

### 2.3 四平台职责

| 平台 | 同步回放 | 字幕导出 | 词汇表 | 录音标记 | 诊断统计 |
|---|---|---|---|---|---|
| macOS | 完整 | 完整 | 完整 | 导入/显示手机标记；桌面录音可复用 | 完整（本机/节点） |
| Windows | 完整 | 完整 | 完整 | 导入/显示手机标记；桌面录音可复用 | 完整（本机/节点） |
| iOS | 录音/可取得的媒体回放 | 可从已有带时间戳结果导出/分享 | 查看与管理可用词典，能力一致 | **必须原生支持** | 查看可靠可得的任务统计 |
| Android | 同 iOS | 同 iOS | 同 iOS | **必须原生支持** | 同 iOS |

若移动端当前的数据同步只包含文本、不包含媒体，先实现本地原始录音的同步回放；对仅保存在电脑的媒体，明确“源音频未在此设备上”，提供安全的手动获取/重新选择路径，不强迫开发无认证的新音频下载 API。

## 3. 功能一：文字与音频同步回放

### 3.1 必达的使用体验

**桌面端**：打开已有完成转写任务，阅读式排版不变；顶部或正文下方出现简洁播放控制区。点击有合法时间戳的段落/句子，播放器定位到对应位置并可开始播放；正在播放时当前段落适度高亮，用户滚离底部时不抢夺滚动控制权。

**移动端**：打开自己录制的音频及已同步的转写，点击文字可跳播，点击播放后能看到当前对应段落；锁屏音频播放控制应遵守各平台能力和音频会话策略。

具体要求：

1. 支持播放、暂停、拖动进度、当前时间/总时长、常见播放倍速（建议 0.75×、1×、1.25×、1.5×、2×，平台无法保证稳定变速时要正确退化）。
2. 点击一个有时间范围的文本块：**seek 到 `start_ms`**；用户若选择“从这里播放”，开始播放；点击与选择/复制操作不能冲突。建议按独立小型播放图标/时间标签操作或在非选中文本点击时跳转。
3. 播放位置变化时以**实际媒体播放时钟**查找覆盖当前播放位置的 `segment_id`；不要依赖推理事件或 UI 计时器估算。
4. 当前段落高亮要低调，保持原定阅读式布局，不能变成满屏密集时间戳。提供“跟随播放”开关；用户手动滚动时暂停自动滚动，允许随时恢复。
5. 支持读到最后一段自动结束；正常暂停/页面切换/打开 History 后保存阅读位置与播放位置，返回可恢复。
6. 如果是视频源，第一版允许只抽取/播放其音频；保留原视频路径和时间映射。如果已有视频预览，优先同步视频位置，不强制新增完整视频编辑器。
7. 对 **多个独立音轨**，最少能选择当前回放轨道（例如“我 / 会议”），每个轨道对应正确的片段时间；允许按照共有会话时间轴查看关联结果。音源切换与暂停/空白区间时不能串轨或误映射。
8. 片段只有粗粒度时间戳：允许按**片段起点**跳转，并给用户轻提示“仅支持片段级定位”；无可靠时间戳：文本正常展示但禁用精确跳播，禁止凭字符比例或 ASR 输出顺序伪造对应时间。
9. 媒体文件被删除、移动、权限失效、远端源文件不可访问时：文本仍可阅读，展示“音频不可用 / 重新定位文件”，不崩溃、不删历史，重新关联需验证长度/指纹，不能把错误文件当成原媒体。
10. 对转写后应用的术语纠错，保持原 segment_id、时间范围和可点击区域；不要因为词长变化造成跳播偏移。

### 3.2 实现建议

- 抽象 `MediaPlaybackController`：`open(media_ref)`, `play`, `pause`, `seek(time_ms)`, `position`, `duration`, `set_rate`, `close`。采用平台成熟音频播放组件，并根据已用技术栈选择 Rust/前端或移动原生桥接；不能把全部媒体一次读进内存。
- 用稳定片段时间区间索引（排序数组/二分查找）实现 `position -> segment_id`。重叠讲话或多轨的高亮规则应明确，比如当前选中的轨道优先，其余轨道并列但不强制跳动。
- 记录 `timestamp_granularity` 和可用精度，用户看到的行为与数据支持能力一致。
- 防止点击时间、重复事件、音频播放状态和 UI 路由导致竞态；长音频（≥3 小时）依旧流畅。

### 3.3 必测场景

- 10 秒短音频、90 分钟课程、3 小时长录音；中文/英文及多段落；点击首/中/末段定位误差落在底层时间戳和播放器可实现的合理范围内，记录实际误差。
- 用户正在选中文本复制时不触发意外跳播；播放中手动滚动不会被界面强制拉回。
- 多音轨麦克风 + 会议输出选择正确；暂停/继续录音形成的时间空缺与标记匹配；模型只提供片段级戳时正确提示。
- 手机录完→Windows 节点转写→结果回手机→点击文字播放手机本地原录音。
- 原文件删除/改名/跨盘移动时正确容错；不影响已有 TXT/JSON 导出和全文搜索。

## 4. 功能四：SRT / WebVTT 字幕导出

> 这里的“第四个功能”指用户确认的**字幕导出**，不是“字母导出”。

### 4.1 必达功能

1. 在 macOS/Windows 现有导出菜单添加 **SRT（`.srt`）** 和 **WebVTT（`.vtt`）**；移动端可从已取得可靠时间戳的转写结果通过系统分享/文件导出提供同类能力。
2. 正确格式：SRT 顺序编号、`HH:MM:SS,mmm --> HH:MM:SS,mmm`；WebVTT 文件以 `WEBVTT` 开头，时间用 `HH:MM:SS.mmm --> HH:MM:SS.mmm`。写入 UTF-8，保留中文、英文、标点及多语言字符。
3. **只从真实模型/后处理支持的时间范围生成字幕**。若只有可信片段级时间戳，就导出片段级字幕；不伪造词级精度。完全没有可信时间戳时禁用或明确说明字幕不可生成，建议改用 TXT/JSON，而不是把全文平均切割成时间码。
4. 适当做文字换行、单条长度与过短/过长字幕处理，并保证与实际片段区间关系可追溯。不得将不同语音段强行拼接成错误时间顺序。可提供简洁选项：是否包含说话人标签（有可信来源才可选）、是否使用校对/术语纠错版本、按指定轨道导出。
5. 多轨录音：默认选择单轨导出；允许按轨道分别导出，文件名安全清晰，如 `lecture_mic.srt`、`lecture_meeting.vtt`。只有在保留可靠公共时间轴与轨道标签时，才提供多轨合并导出；否则不能乱序混合。不同轨道的重叠发言要有明确处理原则。
6. 处理相同/重复/倒序时间戳、零时长、超过媒体末尾、极长片段、换行控制字符等；修正策略可追踪，不能默默抹去内容。字幕切割如缺乏词级/更细时间戳，不允许为了两行美观产生无证据的中间断点。
7. 导出失败要有明确错误信息，生成文件可被常见播放器及字幕软件识别。绝不将 HTML 或富文本包装为字幕文本。

### 4.2 文件示例（用来验证格式，内容为样例）

```srt
1
00:00:01,200 --> 00:00:03,800
大家好，欢迎来到今天的课程。

2
00:00:04,000 --> 00:00:06,500
我们先讨论蒙太奇理论。
```

```vtt
WEBVTT

00:00:01.200 --> 00:00:03.800
大家好，欢迎来到今天的课程。

00:00:04.000 --> 00:00:06.500
我们先讨论蒙太奇理论。
```

### 4.3 必测场景

- 由同一可信片段输入分别导出 SRT/VTT，验证 UTF-8、时码语法、毫秒精度、顺序编号、跨小时（>1h）时间格式与播放器可导入性。
- 未提供时间戳的模型、只有粗分段的模型、词级时间戳模型，以及异常戳都正确处理。
- 多音轨分别导出；混合前后语音重叠不丢片段；字幕版文字符合用户明确选定的文本版本。
- 导出时取消、路径无权限、手机分享目的地取消时不污染既有记录。

## 5. 功能五：词汇表与术语纠错

### 5.1 核心用户价值

用户经常录制专业课程或会议，模型会把人名、电影理论术语、英文缩写等识别错。用户可创建术语词典，例如：

- 错误识别形式：`爱森斯坦` 的常见误写 → 规范形式 `爱森斯坦`；
- `巴赞`、`长镜头`、`蒙太奇` 等专业词汇及其常见误写；
- 自定义的人名、品牌名、课程特定术语（不能将用户私有词典自动同步到未认证 LAN 节点）。

### 5.2 数据与功能要求

1. 桌面端“设置 / 转写”或“术语表”提供统一管理入口；移动端能浏览、新建、修改、删除词条，UI 保持轻量，不增加首页大面积复杂控件。
2. 词条字段建议：`id`、规范写法、可选错误写法集合、可选语言/适用范围（全局/指定项目或任务）、是否启用、更新时间、匹配选项；合理允许说明、导入导出 JSON/CSV（若安全且易维护）。
3. **优先实现转写后的确定性纠错**：针对用户明确录入的误写→正确形式进行匹配，提供“预览替换”“批量应用”“撤销/恢复”；可选择自动应用**严格规则**，但默认保守，不擅自把模糊相近词全局替换。
4. 中文处理避免简单英文单词边界逻辑；英文支持大小写/整词/多词短语；长词优先，避免 `ABC` 与 `AB` 的交叉重叠；对空字符串、循环映射、A→B 与 B→A、重叠冲突建立检测和提示。
5. **原始 ASR 文本永久保留**。词典应用结果以 `TranscriptRevision` 或可追溯规则快照保存，可撤销、重新应用，不能对历史原文做不可逆原地替换。
6. 不破坏 `segment_id`、时间戳、说话人/轨道、书签引用；字幕导出、复制与 AI 总结可选使用原文或纠错后版本，默认保持 UI 当前选择的一致性。
7. 词典版本变化**不能悄悄改写已有历史**。提供明确的“重新应用新词典”动作；记录规则版本、应用时间及发生的变更数。允许按任务禁用词典或选择指定词典。
8. 识别前的 **hotwords / initial prompt / vocabulary biasing**：仅当当前 ASR adapter 实际提供该能力时，通过能力声明显示和应用；能力不支持时不伪装为生效，不向不支持模型硬塞参数。对模型使用的提示词或词典内容应有体积上限、参数验证及失败降级。
9. 隐私：词汇表可能包含敏感姓名及专业资料，默认保存在当前设备本地；若用户明确选择跨设备同步，只有在已有可信同步机制支持时进行。LAN V1.1 未配对节点不可自动收集词典。
10. 持久性：数据库迁移、导入去重、无效行报告、字符编码、跨端一致性及版本恢复都要测试。

### 5.3 特别提醒：正确术语 ≠ 绝对准确

不能宣称纯规则替换能修复模型所有识别错误。对于容易歧义的词（人名与普通词同音等）应提供人工确认模式。避免 AI/模糊匹配对整篇转写进行静默改写。

### 5.4 验收

- 用户添加两条误写规则，实际转写结果能预览差异、应用、更换词典后重新应用并撤销；原文完全可恢复。
- 中文/英文、大小写、叠词、重叠规则、空值和冲突映射安全处理。
- 在 Mac 上建立词典并通过已有被授权的同步/导入方式转到 Windows 或手机后，词条语义一致；不暗示 LAN 计算自动保证同步。
- 术语替换后，音频点击跳转和 SRT/VTT 字幕的时间仍对应原始片段。

## 6. 功能七：手机录音「重点标记」

### 6.1 产品交互

在 iOS 和 Android 的录音界面加入一个明显但克制的 **「标记」按钮**（书签图标）。

- 录音中点击一次，立刻记录当前音频时间并显示轻反馈，例如“已标记 12:35”；操作不能中断录音。
- 用户可以连续创建多个标记，可选短备注如“重点”“考试范围”“待确认”；**不强制输入文字**，尤其锁屏或课堂场景要一键完成。
- 录音结束进入该录音详情页，有“重点标记”时间列表，点击直接从对应时间回放。
- 转写结果回到手机后，每个标记自动关联其对应/最近的**可靠时间范围**片段；点击标记跳到相应文字，若当前模型没有可用时间戳则仅支持按音频时间跳转并提示关联不可用。
- 从手机录音上传到 Windows/macOS 节点转写时，标记随**任务元数据**保留，并可以在桌面端的该录音详情页查看和操作；不要求把标记烘焙进音频波形。
- 允许标记重命名、删除、排序（按时间）、编辑备注；删除需符合既有交互习惯，撤销机会优先。

### 6.2 技术细节

1. 使用当前录音 session 的**单调时间基准与实际音频时间映射**，不是 `Date.now()` 直接减开始时间。必须处理录音暂停/继续、音频中断、音频缓冲和掉帧：标记对应的是**回放时音频中的位置**。
2. 标记至少包含 `marker_id (UUID)`、`recording_id`、`track_id`（如适用）、`media_time_ms`、`created_at`、`label`、`note`、`sync_state`、`version`。
3. 标记持久化不依赖录音结束：点击后立即安全写入本地数据库，App 意外退出后能恢复已记录标记。
4. 标记与上传任务保持独立幂等 ID；重试上传、网络断开、节点重新启动、跨设备同步后**不能重复出现**。使用已有任务元数据扩展协议；服务端不支持时需进行兼容版本判断和客户端本地保留，避免因新字段导致音频上传失败。
5. 若录音还没开始、已结束或音频尚未可用，不能生成虚假的标记时间；用户连续点击在极短时间内可设置轻去抖，但不应错误丢失用户明确意图。
6. iOS 锁屏/Live Activities/控制中心快捷入口、Android 通知快捷操作属**可选增强**：若开发与测试成本合理，可增加系统许可的“添加标记”入口，但主界面一键标记是必达；不要绕过系统限制宣称所有锁屏状态都能点标记。
7. 设备离线、电脑关机、手机尚未上传时，标记功能完全可用；它首先是本地录音功能，不依赖联网。
8. 用户原有音频/视频文件若不是由手机录制，可选择后续支持手动加书签；本任务重点是手机**录音时实时标记**。

### 6.3 必测场景

- iPhone 和 Android 真机：录制 30 分钟以上，期间至少 5 次标记，锁屏前后/蓝牙音频状态改变后检查时间映射。
- 暂停 2 分钟后继续录制：标记的媒体位置不包含暂停导致的空白时长（除非录制格式本来明确保留该空白；以**实际回放时间轴**为准）。
- 录制中断、App 意外退出、上传失败后恢复标记；上传重试不会复制标记。
- 手机上点标记回听，桌面显示相同的实际时间；转写后能跳到正确段落。

## 7. 功能十：任务诊断与性能统计

### 7.1 设计原则

**普通用户只看到简洁进度，高级用户才展开“任务详情 / 性能”**。不能因加入诊断功能使首页变成密集仪表盘，更不能为了显示数字而推断或编造不存在的测量。

### 7.2 每个任务建议记录的指标

| 指标 | 定义 / 要求 | 无法测量时 |
|---|---|---|
| 源音频时长 | 经解码/媒体探测得到的真实时长，单位秒 | 显示“未知” |
| 任务端到端总耗时 | 从任务开始到完成的实际墙钟时间；与排队时间分离 | 显示可获得阶段 |
| 排队等待时间 | 在负责执行的**节点队列**中等待的时间；本地意图队列需区别标注 | 不冒充节点耗时 |
| 上传/传输耗时 | 手机/桌面远程提交音频的持续时间 | 本地任务不显示 |
| 音频提取与预处理 | 解码、重采样、降噪等阶段分别计时（能测则分开） | 标为阶段不可用 |
| 模型加载时间 | 本次**实际发生的加载**耗时；复用驻留模型时显示“已驻留/本次未加载” | 不虚构加载成本 |
| ASR 推理墙钟耗时 | 模型实际推理计算阶段的耗时，清楚排除上传和排队 | 数据缺失则未知 |
| RTF（Real-Time Factor） | `ASR 推理墙钟耗时 / 参与推理的音频时长`，越小越快 | 任一值未知不计算 |
| 音频处理速度 | 可选显示 `1 / RTF` 倍实时（如 5×）；与 RTF 的定义一致 | 不额外估算 |
| 设备及后端 | Mac/Windows、CPU/GPU 类型（确知时）、引擎、ASR 模型标识、量化/运行格式（确知时） | 保留未知标识 |
| 内存 | 进程峰值 RSS / 可测量的 GPU 内存等，**注明口径、采样范围与测量方法** | 不支持则隐藏或写未知 |
| 错误与重试 | 失败阶段、可脱敏错误码、重试次数、取消原因（若有） | 无则不显示 |

**例子**：模型推理用了 30 秒，实际处理音频长 300 秒，则 `RTF=30/300=0.1`，即推理速度约为 `10× 实时`。这只是公式示例，UI 必须显示真实测量值。

### 7.3 关键技术约束

1. 使用**单调时钟**测量本机各阶段耗时，日志时间可另存墙钟时间；禁止直接用系统时钟跳变造成负耗时。
2. 每个任务阶段使用明确状态机及时间点，不可重复计入时间。任务取消或失败时保留已经真实采集的诊断数据，并标注不完整。
3. LAN Compute：**计算耗时由真正执行 ASR 的计算节点测量与返回**；客户端不要根据网络等待时长估算远程模型推理速度。上传/下载耗时则由客户端或双方带口径记录。
4. 多任务节点串行时，排队时间与运行时间分开；多节点并行不意味着单节点并行推理。
5. **内存指标是重点易错项**：`RSS`、进程私有内存、系统空闲内存、模型文件大小、GPU 已分配内存不是同一个概念。不得拿模型磁盘占用冒充 RAM 或 VRAM 使用量；“峰值”需要实际观测窗口，并注明是否覆盖模型加载/推理全程。
6. 采样频率克制，默认不开高频诊断轮询，不为了显示图表造成明显 CPU、电池、I/O 负担。建议事件计时 + 低频或按需内存采样，性能开销要测量。
7. 本地存 SQLite 或已有诊断表，按任务保留必要摘要；完整详细日志有大小/保留周期上限，支持用户主动导出已脱敏的诊断报告。
8. 不能在性能日志中记录转写正文、原始音频、API Key、用户完整文件路径、局域网秘密令牌或其他敏感数据；诊断报告对本地 IP、用户名、目录做脱敏。
9. 同一设备不同运行后端结果不能直接不加说明地横向排名。可提供历史任务比较，但应展示音频时长、模型与硬件，不制造“模型准确率”或未经验证的排名。

### 7.4 UI 验收

- 在现有任务/历史详情中通过一个不显眼的“详情 / 性能”入口查看：模型、设备、源时长、排队、加载、推理、RTF、可得内存和错误诊断。
- 空闲时没有因诊断功能额外常驻大型进程；局域网节点无需为了 UI 请求就自动加载模型。
- 远程任务断线再连接后，保留节点此前已经持久化的可得统计，不可重复累计耗时或把未知写作 0。
- 比较同一录音的两次任务，可以分别看到它们自己的运行数据，不因为文件同名覆盖记录。

## 8. 跨功能一致性与风险处理

### 8.1 原文、时间戳和导出的关系

一份原始 ASR 结果及其人工/术语修订版应引用**同一组稳定片段及媒体时间范围**。界面用户可以切换使用原文或修订文本：

- 点击文字回放：始终依据原始可信时间范围定位；
- SRT/VTT：选择导出的文字版本，但时间范围仍是可信媒体片段时间；
- 手机标记：依据会话媒体时间，引用落在该时间附近的片段 ID；
- AI 总结：默认使用用户明确选择的文本版本，但不得编辑覆盖原文；
- 诊断：绑定某次运行任务与确切 ASR 模型，不因为用户后来纠错而重算历史速度。

### 8.2 跨平台与跨设备兼容

- 为共享数据定义版本号（必要时 `schema_version`/`feature_capabilities`），旧客户端遇到新字段应忽略并保持基本转写可用。
- 对 `RecordingMarker` 等元数据做到幂等增量同步；如某端只具备最旧 LAN 协议，不能因为附加元数据导致普通任务失败。
- 设备发现并不等于身份认证。既有 LAN V1.1 **未配对**，不得默认将手机私人音频、词典、诊断或媒体反向传给任意发现的机器；坚持使用用户明确选定的节点，公开测试文档中如实指出风险。若已有安全配对功能，则优先复用。
- 手机/桌面间网络断开时，本地录音与书签必须独立存在；恢复后按既有恢复协议补齐任务结果，不能重复创建同一转写或书签。
- 多音轨遵循“每节点串行 ASR / 多节点可并行”的既有调度语义，不因为追加字幕/回放就改动队列策略。
- 旧版历史任务无时间戳时，应以真实降级体验呈现，不得在数据库迁移时批量伪造时间戳。

### 8.3 用户隐私、访问与权限

- 原始录音、全文转写、词典默认本地持久化；任何上传遵守已有用户指定目标与授权。
- 不请求与当前功能无关的宽泛文件或录音权限；不擅自开启后台麦克风。
- macOS/Windows/iOS/Android 的音频权限、媒体库或文件访问权限均沿用平台标准路径。
- 明确区分**本机录音文件**与**远端计算节点缓存文件**，不因为远端缓存 TTL 到期删除客户端原始录音。

## 9. UI 与交互约束

本产品原有方向：Apple 风格的精致、克制、轻量 UI，借鉴 Raycast 的效率感；不是全屏“音频工作站”，不要无故增加常驻侧栏或大面积卡片。**保留已有阅读式主结果页与左侧导航**。

1. **桌面阅读页**：以转写内容为主体；仅在源音频可用时增加小型播放条、微弱当前段落高亮、按需“跟随播放”。
2. **桌面导出**：现有 TXT/JSON 基础上添加 SRT/VTT，模型无可信时间戳时显示明确原因；不展示不可用的假选项。
3. **术语管理**：设置下的简洁词典列表与编辑弹层，支持批量导入/撤销；转写历史页显示正在查看的文本版本。
4. **手机录音页**：标记按钮与计时器相邻，单手可点，触控面积满足系统可用性；录音过程中绝不弹出会打断录音的必填窗口。
5. **任务详情**：性能信息默认收起，进阶用户再展开；异常状态提示简洁但具体。
6. 深浅色主题、键盘操作、屏幕阅读器、无障碍文本放大、动态布局和中英文本本地化不回退；既有 GitHub README 继续英文优先、中文在后。
7. 尽可能提交**真实功能截图**，不要把概念图冒充实测。Windows/macOS UI 保持行为一致，系统标题栏和系统风格遵守各自平台习惯。

## 10. 开发实施阶段与独立验收门槛

### Phase 0 — 审计与方案冻结

- 检查 `macOS / Windows / iOS / Android` 的实际能力矩阵，列出哪个平台已经有播放器、字幕、词典、标记、诊断的部分代码。
- 复核现有 ASR adapter 是否提供 segment start/end/word timestamps，哪些模型只有纯文本，统一能力声明。
- 输出最小迁移和测试策略，明确旧数据兼容以及媒体/轨道时间轴。
- **验收**：有真实代码证据，核心方案存入 ADR；不通过口头臆测确认已有功能。

### Phase 1 — 数据模型与时间轴底座

- 完成 segments/时间戳精度、修订文本、录音标记、词典、任务诊断的最小必要数据库迁移和共享协议字段。
- 将原始时间戳/媒体轨道与显示文本解耦，支持单轨/多轨、历史记录升级。
- **验收**：旧历史继续可用，数据库测试与向后兼容测试通过。

### Phase 2 — 桌面音文同步回放 + 字幕导出

- macOS 和 Windows 各完成媒体播放控制器及 UI 绑定，真实文件点击跳转，History 保持阅读/播放位置。
- 导出 SRT/VTT 和真实播放器兼容性验证。
- **验收**：两台真实桌面平台测试，10 秒、90 分钟、3 小时媒体，具有可信/无可信时间戳的模型均显示正确行为。

### Phase 3 — 四端词汇表与术语纠错

- 完成词典持久化、增删改查、规则引擎、预览、撤销、版本引用；移动端管理 UI 按已有技术栈实现。
- 对模型适配器中真正支持的热词能力单独做声明与测试。
- **验收**：中文+英文规则、冲突/循环检测、历史原文可完全恢复、字幕与同步回放不偏移。

### Phase 4 — iOS/Android 一键录音标记与跨设备关联

- 手机录音中加入书签事件，记录实际媒体时间，录完可回听；持久化与幂等元数据同步。
- 桌面端读取/呈现标记，转写结果可靠关联时跳转文字。
- **验收**：双平台真机，暂停/恢复、意外终止、上传重试、节点暂时离线均不丢书签也不重复。

### Phase 5 — 四端诊断和性能统计

- Rust 任务核心/计算节点记录真实阶段事件、任务级计时和可行的轻量内存统计。
- 手机/桌面显示收到的真实节点诊断信息，脱敏导出。
- **验收**：RTF 公式正确，加载缓存情况下不会误报加载时间，远程排队与推理时间区分，空闲资源回归合格。

### Phase 6 — 回归测试、文档、安装包、发布

- 四端回归：源文件导入、录音、模型、CLI/MCP、LAN 上传队列、历史搜索、已有 AI BYOK 功能、导出、异常恢复。

## 11. 详细测试清单（不得遗漏）

### 11.1 单元/集成

- [ ] 时间戳合法化：负数、零时长、溢出、倒序、小时边界、重叠片段、媒体时长不一致。
- [ ] `position ↔ segment_id` 查询：含多轨重叠、编辑后文本长度变化。
- [ ] SRT/VTT 语法：中文 UTF-8、分毫秒时码、顺序、换行、无时间戳拒绝导出。
- [ ] 术语规则：中文无空格、英文整词与大小写、冲突规则、循环规则、规则更新与撤销。
- [ ] 标记时间：开始、暂停、继续、录音中断、恢复、重复上传、跨设备时区变化不影响音频 offset。
- [ ] 诊断计时：节点与客户端时钟不同、任务失败/取消、远程排队、加载复用、RTF 分母为零。
- [ ] 旧数据库/旧任务兼容，无需全面重置用户数据。

### 11.2 真机/端到端

- [ ] macOS：点击片段正确跳播、播放跟随、长音频稳定、导出字幕可用。
- [ ] Windows：同 macOS，包含不同音频/视频编码与原文件丢失恢复。
- [ ] iOS：实际锁屏录音、重点标记、暂停续录、断网恢复、标记与远程文字对齐。
- [ ] Android：与 iOS 等效，针对不同 Android 版本及至少一台真实设备测试后台行为。
- [ ] LAN Compute：Mac→Windows 和手机→电脑，断线重连、幂等任务和标记、远端真实性能值。
- [ ] 多音轨：麦克风 + 应用音轨独立导出、定位和高亮；不以系统混音冒充。
- [ ] 回归：未启用新增模块的用户不受影响；没有新增不必要的大型常驻进程。

测试必须记录：设备、OS 版本、应用 commit、模型家族与版本、样本时长、实际结果、日志/截图证据、失败项目。真实个人素材仅由用户已经授权的受控设备访问，调试报告脱敏。
