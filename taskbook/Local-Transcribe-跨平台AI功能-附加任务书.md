# 附加开发任务：Local Transcribe 跨平台 AI 功能

> 归档说明：本文件为 2026-10-23 用户下发的任务书原文归档（正文未改写）。
> 执行顺序：在既有任务书（Windows LAN Early Beta 发布收尾 → Windows 精准应用录音 → iOS/Android 移动端）完成后实施。

请在现有开发任务完成后，为 **Local Transcribe 的 macOS、Windows、iOS 和 Android 四个平台**增加统一的 AI 内容处理功能，保持现有 UI 设计语言，不影响本地语音转写、录音及局域网计算功能。

### 一、AI API 接入

采用 **BYOK（用户自带 API Key）** 模式，不提供官方付费 AI 服务。

用户可以自行配置：

- API Base URL（支持自定义第三方中转地址）
- API Key
- 模型名称（Model ID）
- 保存多个 API 配置并快速切换
- 测试连接

优先支持 OpenAI-compatible Chat Completions API，采用可扩展适配器架构，方便以后支持其他协议。

### 二、AI 功能

在电脑端和手机端的转写结果页面增加简洁的「AI」入口，提供：

1. **AI 总结**：简短、标准、详细三种模式。
2. **会议纪要**：整理议题、结论和待办事项，不编造责任人或时间。
3. **课程笔记**：按照章节、知识点、重点概念整理内容。
4. **AI 问答**：允许用户针对当前转写内容提问，优先依据原文回答。
5. **自定义提示词**：用户可以创建、编辑、保存和复用处理模板。

AI 结果与原始转写内容分别保存，不能覆盖原始识别文本。

### 三、长文本处理

支持数小时录音产生的长篇转写文本。

根据模型上下文容量和 Token 预算进行智能分段、分段处理与结果整合。支持进度显示、取消、失败重试，尽可能保留原文段落引用，避免长文本截断或信息遗漏。

### 四、跨平台与安全

- macOS、Windows、iOS、Android 使用统一的功能定义及结果数据结构，尽可能复用核心逻辑。
- API Key 存储在各平台的系统安全存储机制中，不得明文写入数据库、日志或 Git 仓库。
- 默认仅在用户主动使用 AI 功能时发送必要的转写文本，不上传原始音视频。
- 首次调用外部 AI 前明确告知用户文本将发送到其配置的服务商。
- 不向局域网计算节点传输 API Key，AI 请求默认由发起操作的设备执行。
- 支持请求超时、取消、限流处理及有限次数重试，避免无限消耗 Token。
- 保持原有离线转写功能完全可用，未配置 AI 服务时不影响其他功能。
