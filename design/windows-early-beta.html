Local Transcribe — Windows Early Beta 冻结灰度功能设计稿

本文档为 Windows Early Beta 的固定功能设计稿（灰度）。文案、布局、尺寸、间距、颜色、组件状态、交互与转场均以此为准。 灰度色板是唯一色源；本稿不引入任何彩色。macOS 端视觉不按本稿改动（macOS 保持现行主题，最终设计另行决定）。 窗口基准尺寸 1120×720，最小 940×620；内部布局按 8pt 网格（间距取自 --sp-1..--sp-6）。

任务状态（固定枚举）
待传输 → 传输中（显示 N/M 分片）→ 排队中 → 转写中 → 后处理 → 已完成 / 已取消 / 失败 / 部分失败。传输失败或节点离线：显示「中断，可续传」。
配对交互
「配对…」弹层：输入 6 位配对码或粘贴令牌 → 成功后 chip 变「已配对」；失败文案「配对码无效或已过期」。同一节点重复配对直接更新令牌。
管理弹层
节点详情：能力（GPU/CPU、模型）、存储用量、任务数、「取回结果」「导出收集」「忘记此节点」。
离线
节点 3 秒 ping 失败即 chip 变「离线」（虚线），进行中传输显示「中断，可续传」；恢复后自动重试续传（2s 间隔，最多 3 次）。
转场
表格行状态 chip 变化 160ms 交叉淡入；进度条同 §1。弹层 220ms scale(0.96→1)+淡入，关闭 160ms 淡出。

§7全局拖拽 · 识别文件格式转换

松开以添加到转写队列 已识别：MP3、WAV、M4A、FLAC、MP4、MOV、MKV、WebM、AVI 其他格式：松开后提示「不支持的文件格式」
行为（固定）
拖拽进入窗口即显示全窗蒙层（含主窗口以外的所有视图）；有效文件高亮，无效文件显示拒绝文案；混合拖放按可识别部分添加并提示「已添加 N 个文件，跳过 M 个不支持」。
格式识别
先扩展名白名单，再读文件头校验（mp4/mkv 的 ftyp/Matroska 魔数）；不一致按不支持处理。
转场
蒙层 120ms 淡入/160ms 淡出；拖放完成 toast「已添加 N 个文件」2s。
