更新记录

应用启动时会读取本页同目录的 updates.json（纯静态文件，一次普通请求，不含任何标识或使用数据）。发现新版本时，应用会弹窗询问；点“去下载”才会打开 GitHub。可在 设置 → 自动检查更新 关闭。

1.7.0

2026-11-02
  • 去掉文件访问白名单。旧版本要求先把文件夹加进 access.json，否则拒绝读取；现在删掉了整套机制——GUI、命令行和 MCP 都能直接读取当前用户可访问的任意绝对路径，设置页不再有“允许访问的文件夹”，也没有 roots 命令。
  • 边界仍然存在：服务只监听当前用户的本地 socket，其他账户或其他电脑连不上。
  • 新增启动时检查更新（默认开启，可在设置里关闭），更新记录就在本页。
  • 首页历史列表会在命令行或 MCP 写完结果后自动刷新，不用重启应用。

1.6.0

2026-11-01
  • MCP 服务器与 local-transcribe 命令行随安装包一起分发，装完 GUI 即可使用，不再需要 cargo build。
  • 设置页新增“复制 MCP 配置”和“安装命令行工具”（~/.local/bin，不需要 sudo）。
  • 去掉 beta 标记，转为正式版；三个入口共用同一份数据目录。

Changelog

On launch the app reads updates.json next to this page — a plain static request, with no identifiers or usage data. If a newer version exists, the app asks before opening GitHub. You can turn this off in Settings → Check for updates.

1.7.0

2026-11-02
  • The file-access allow-list is gone. Earlier builds required adding a folder to access.json before anything could be read; that whole mechanism was removed. The GUI, CLI and MCP now read any absolute path the current user can open, Settings no longer lists folders, and there is no roots command.
  • The boundary that remains: the service only listens on the current user's local socket, so another account or computer cannot reach it.
  • New: check for updates on launch (on by default, can be turned off). The changelog is this page.
  • The home history list refreshes when a CLI or MCP job writes a result, without restarting the app.

1.6.0

2026-11-01
  • The MCP server and the local-transcribe CLI ship with the app, so no cargo build is needed.
  • Settings can copy a ready-made MCP config and install the CLI into ~/.local/bin without sudo.
  • Beta label dropped; GUI, CLI and MCP share one data folder.
